Use the authorized task's transport in input/frontend-transport.json through deliver.py. It contains a task-bound broker capability, never the Hub's shared credential. HUB_URL/HUB_TOKEN are also supported for authorized direct execution. The internal service is http://frontend-resource-hub:8080; never invent credentials or expose tokens in HTML, prompts or delivery files. Native sandboxes have no external network: use the supplied loopback broker URL and authorization for catalog queries, not the internal hostname. If transport is unavailable, preserve generated files and state that preview is unavailable.

Query GET /api/v1/resources, /themes, /templates?q= and /components. Read the selected template and component details by ID. Use the exact file URLs and dependency order returned by the resource manifest. Tabler already includes Bootstrap styles: select one style framework. Charts use ECharts 6. Preserve original business data, calculations, labels and units. Bind authorized data to window.BUSINESS_DATA using safely serialized JSON; templates contain empty states, not production sample data. Implement actual task interactions and business API bindings; a local confirmation is not a completed server-side approval.

Choose one data binding strategy for each page. Keep assets/hub/bind.js with window.BUSINESS_DATA, or remove it when implementing custom renderers and event handlers. Loading both can clear populated tables or apply conflicting query handlers. Check visible cell values and actual filter/confirmation outcomes against authorized source data. Script text containing a value does not prove that the value is displayed.

POST /api/v1/preview with Authorization: Bearer token and JSON {"html":"..."}. Poll GET /api/v1/preview/{id}/result until status is passed or failed. Read report.errors and inspect both desktop and mobile screenshots through authenticated /{id}/desktop.png and /{id}/mobile.png. Declare required elements with data-preview-required and safe local test controls with data-preview-click. Do not declare actions that mutate business state as preview clicks. Browser validation does not establish business or numerical correctness.

Repair the actual HTML through native Cline editor tools based on the report and screenshots; resubmit it to preview. Keep prior HTML hashes, error reports, changes and subsequent results as repair-history.json in the task output. Runtime's existing budget, cancellation and retry policy controls the loop; this Skill adds no model-call limit. A failed or missing preview cannot be marked passed.

Use [deliver.py](deliver.py) with the generated HTML path and --output path, from the authorized workspace, to preview, retain attempt reports, safely extract the offline bundle and merge Runtime artifact selections. It reads HUB_URL and HUB_TOKEN from the authorized environment. An exit code of 2 preserves a failed preview for Cline to repair; other failures retain the explicit error. Download the authenticated /api/v1/preview/{id}/bundle only after bundle=true. It includes original index.html, standalone.html, dependencies.json, manifest.json, validation-report.json, assets, themes and screenshots. Validate standalone.html in an offline browser and verify actual business mappings and controls before acceptance.

Use the task's existing delivery_manifest.json selection contract, schemaVersion coding_node_delivery_selection.v1, declaring every deliverable with path and type (SOURCE, REPORT, CHART, RESULT, TEST or AUXILIARY). Merge with existing selected artifacts. Runtime computes hashes, trusted task bindings and immutable Silo uploads. Keep HTML, screenshots, dependencies, repair history and validation report together under tasks/{taskId}/frontend within the authorized output root. Do not create a parallel task lifecycle or claim Silo delivery before Runtime's archive receipt. When validation or upload fails, preserve files and the explicit failure state.
