Cover, executive summary, KPI cards, charts, analysis conclusions, sources and appendix are available semantic components. A cover must not push the executive summary beyond page one. It builds report.html, report_manifest.json, evidence.json, charts/ and quality_report.json inside the caller's authorized output folder. Its input model uses title, reportType, period, theme, summary, metrics, sections, sources, claims and charts. See its functions for the compact schema. Adapt HTML content/layout if helpful while retaining evidence anchors and shared tokens. Escape untrusted content. Never execute source-provided HTML or JavaScript.

Use existing platform resource service URLs only when advertised and version pinned. Package identical local assets for restricted networks; do not introduce public CDN dependencies. Pass an existing local ECharts bundle to build(); no repeated downloads. Without it deliver visible chart data tables and mark interactive validation incomplete. Browser validation must actually render desktop, mobile and print, check console errors and chart instances; HTML parsing alone is not rendering. Quality status remains incomplete until independent browser evidence is available. Declare all generated companions and assets using the existing artifact selection/archival protocol.

For report images and charts, load html-image-assets from the advertised Skill index. Keep generated image files and preview screenshots separate from report source and model context.

## Report page layout and overflow

Use the actual report content to size cards, charts and tables. Allow grid and flex children to shrink (`min-width: 0`), and stack adjacent panels on narrow screens. Let titles, captions, source URLs and tab controls wrap. Keep intentional horizontal scrolling within a wide table's own wrapper, with an accessible label if it needs keyboard focus. Avoid hiding overflow at page level, where it can conceal clipped labels, navigation or evidence.

Keep chart containers within the card width. For static figures, use `display: block; max-width: 100%; height: auto` on the image. Use readable figure sizes with a nearby caption, legend or data table. For interactive figures, size the chart to its container and ensure each newly visible tab redraws at the panel's actual width. Check print separately: tables should remain readable without scrolling, and print charts should have their own complete legends or adjacent tables.

Preview the final HTML at a desktop width and a narrow viewport such as 360 px, including the report in its viewer when available, at 200% zoom, and in print. Open every chart tab and inspect the actual charts, including the longest labels and smallest categories. Check that the document has no horizontal overflow (its scroll width should fit the viewport), controls are reachable, and charts, legends and captions do not overlap or clip. Fix confirmed layout defects in the report or plotting code and rerender. If the task cannot render a viewport or print, record which checks remain unverified.
