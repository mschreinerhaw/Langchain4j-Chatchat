name: report-designer
description: Design platform professional HTML reports with reusable themes, accessible layouts and offline deliverables when professional reporting is enabled.
---

This is the platform default professional report design guidance when enabled. Keep the advertised reportMode and delivery contract. No-report tasks remain no-report tasks. Existing Managed Python rows/visualReport and native delivery_manifest.json contracts remain authoritative; these companion files never replace required outputs or authorize new paths.

Choose sections and presentation freely for the business question. Lead the first page with decision, scope, material limitations and three to six useful metrics. Reuse assets/report.css and assets/report.js; use corporate-blue or financial-research theme variables. Cover, executive summary, KPI cards, charts, analysis conclusions, sources and appendix are available semantic components. A cover must not push the executive summary beyond page one. Avoid decorative charts. For finance consult financial-report-analysis; for charts consult chart-designer; review evidence with evidence-reviewer.

Use scripts/reportkit.py as a reusable Python module (importlib is suitable for skill paths). It builds report.html, report_manifest.json, evidence.json, charts/ and quality_report.json inside the caller's authorized output folder. Its input model uses title, reportType, period, theme, summary, metrics, sections, sources, claims and charts. See its functions for the compact schema. Adapt HTML content/layout if helpful while retaining evidence anchors and shared tokens. Escape untrusted content. Never execute source-provided HTML or JavaScript.

Use existing platform resource service URLs only when advertised and version pinned. Package identical local assets for restricted networks; do not introduce public CDN dependencies. Pass an existing local ECharts bundle to build(); no repeated downloads. Without it deliver visible chart data tables and mark interactive validation incomplete. Browser validation must actually render desktop, mobile and print, check console errors and chart instances; HTML parsing alone is not rendering. Quality status remains incomplete until independent browser evidence is available. Declare all generated companions and assets using the existing artifact selection/archival protocol.

The existing frontend-design Skill supplies task-bound resource catalog and preview transport through input/frontend-transport.json. Reuse its deliver.py query/preview helper for platform assets and browser evidence; do not access the Hub token or create a second preview service. Shared report resources are also registered as professional-report in the Hub resource catalog. For preview HTML, inline the local shared CSS/JS or use catalog asset URLs, then retain the Hub's offline bundle and immutable preview evidence alongside the report companions. Copying a browser result from another report is invalid.
