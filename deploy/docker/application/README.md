# Runtime OS application candidate images

This directory packages the current API, MCP service, and Node Coding Agent. PostgreSQL and OpenSearch stay in their existing containers. The Compose file uses separate PostgreSQL databases and an isolated OpenSearch index, and keeps Node on an internal network that cannot reach MCP directly. A small Nginx sidecar exposes Node to Java only on the API container's loopback interface, as required by `ClineCodingAdapter`. A second Nginx gateway exposes authenticated API/MCP routes on ports 18100/18101; internal callbacks and actuator routes return 404. The application ports 18180/18190 remain on host loopback. Set `PUBLIC_BIND_ADDRESS` to the intended LAN interface (default: all interfaces), and terminate TLS at the site's ingress when required.

Build on a Linux/amd64 Docker daemon from the repository root. Supply the Docker CLI binary from a trusted Docker installation compatible with the destination daemon; `Dockerfile.mcp` copies only that CLI, since the MCP service launches the existing Python Sandbox through the host Docker socket.

```powershell
./deploy/docker/application/build-images.ps1 -DockerCliPath ./target/docker-application-build/mcp/docker -Tag 9cc5ac8f-stage
```

The script installs frontend dependencies from the lockfile, builds the web application into `target/docker-application-build/frontend`, and packages that matching output into the API JAR without rewriting versioned static sources. The `container.image=true` Maven profile excludes local key files, licenses, private PEM files and `.env` files from first-party JARs; existing local files are retained. It checks local index resources and scans both application JARs and nested first-party libraries for deployment secret files before building all three images, pulling the pinned Nginx proxy image, and exporting one archive with a SHA-256 digest. `-SkipMaven` reuses existing JARs but still performs both checks; a successful backend-only build alone does not establish image completeness. These filename checks are not a general secret-content scan. The Docker CLI is an explicit build input and must be recorded alongside that digest. Deployment credentials and licenses must come from the external mounts and environment files described below.

On the destination, create separate API/MCP PostgreSQL databases with the matching files under `database/init/postgresql/`, then prepare root-readable-only `api.env`, `mcp.env`, and `deployment.env`. `deployment.env` must set `STAGE_ROOT`, `API_IMAGE`, `MCP_IMAGE`, `NODE_IMAGE`, `NODE_PROXY_IMAGE=nginx:1.27.5-alpine`, `API_INTERNAL_KEY_FILE`, `MCP_INTERNAL_KEY_FILE`, `CODING_AGENT_SHARED_SECRET_FILE`, `CODING_AGENT_NODE_SECRET_FILE`, and `MODEL_CONFIG_FILE`. Copy `node-proxy.conf` to `$STAGE_ROOT/config/node-proxy.conf`. The Node secret file must contain the same secret as the API file and be readable by UID 1000/GID 32101 (for example, root:32101 with mode 0640); the host copy must stay inside the private stage directory. `api.env` and `mcp.env` supply the corresponding PostgreSQL URLs, users, and passwords. Point the API OpenSearch settings to the existing cluster and use a distinct stage index name. Run:

```bash
docker load -i /opt/runtime-os-docker-stage/images/runtime-os-app-stage-9cc5ac8f.tar
docker compose --env-file /opt/runtime-os-docker-stage/config/deployment.env \
  -f /opt/runtime-os-docker-stage/compose.yaml config -q
docker compose --env-file /opt/runtime-os-docker-stage/config/deployment.env \
  -f /opt/runtime-os-docker-stage/compose.yaml up -d --no-build
```

Copy `public-gateway.conf` alongside `node-proxy.conf` under `$STAGE_ROOT/config`. Run `sh host-license-identity.sh HOST_NIC` on the destination host and add its output to `deployment.env`. `MCP_HOST_MAC_FILE` must name the host device NIC's `/sys/class/net/HOST_NIC/address` file. Compose mounts that single sysfs file read-only at `/run/license/host-mac`, with automatic host-path creation disabled; no host networking or extra container privileges are needed. MCP's `chatchat.license.host-mac-file` setting selects this identity exclusively. A missing or invalid configured identity fails closed, with no fallback to container MACs. The machine code and MAC-based signed license remain stable across container recreation. Bare-host deployments without this setting retain existing NIC discovery.

Use the existing signed license when it already matches the selected host NIC. Otherwise request a license for that host MAC through the license center while preserving the authorized entitlements. Verify `/api/v1/license/status` reports the host MAC and `VALID` after two container recreations. Changing hosts or the licensed host NIC requires a license change; changing the container MAC does not. On a virtual machine this identifies the VM's installed device NIC, not the hypervisor's physical adapter. Never bake the license, signing key or license-center credentials into an image.

The current init SQL can trail entity changes. An isolated candidate may use Hibernate `update` once to bootstrap its empty databases, then restart with `SPRING_JPA_HIBERNATE_DDL_AUTO=validate`. Production must use reviewed migrations. The candidate requires a published Python environment in its own MCP database before Coding Agent analysis can run. The MCP container has the host Docker socket and must be treated as a privileged application component. Do not route production traffic until the full Runtime OS gate and live QA/data-analysis acceptance pass. `docker compose ... down` stops only the candidate containers and leaves existing PostgreSQL, OpenSearch, and application data untouched.

The 2026-10-17 candidate returned `SERVER_MISMATCH` after loading the host license inside Docker. The initial 2026-10-18 container-MAC issuance receipt remains in the remote private evidence directory. The deployment now uses host NIC identity so application upgrades do not require container-specific reissuance. Deployment verification evidence must distinguish this host-identity configuration from the earlier container-MAC candidate; licensing alone does not certify the Runtime OS acceptance gate.
