## 存储要求修正

`/mnt/disk01` 是旧服务器扩容目录，不是产品前提。支持一块系统盘，首次运行通过页面分别选择平台目录与应用目录；独立挂载检查由管理员显式开启。容量不足、目录只读、符号链接逃逸、所选文件系统变化时拒绝相关操作，不自动切换目录。

93 实际只有一块 200 GB 磁盘，根目录为 XFS；未创建 `/mnt/disk01` 挂载。平台数据使用 `/opt/ops93/data`，应用根目录 `/opt/rt93`，Runtime 实例目录 `/opt/rt93/72cc-4a00448cad40`。

## 干净服务器安装

基础条件为 Linux/amd64、JDK 17+ 和足够空间。部署业务需要可连接的 Docker；平台自身启动不要求 Docker、Runtime 或业务数据库可用。

1. 校验发行目录 `SHA256SUMS`，将平台 ZIP 解压到空目录，例如 `/opt/deployment-ops-source`。
2. 如需源码安装，查看 `release.json` 的版本和源码提交，执行：

   ```sh
   java scripts/BuildNativeOffline.java \
     --runtime build/boot-runtime.zip --output lib/deployment-ops-source-built.jar \
     --version VERSION --source-commit SOURCE_COMMIT
   OPS_BIND=0.0.0.0 java -jar lib/deployment-ops-source-built.jar
   ```

   直接使用发行 JAR 时执行 `OPS_BIND=0.0.0.0 java -jar lib/deployment-ops.jar`。
3. 访问管理端口 19240，输入控制台安装令牌，选择可写目录、检查容量并设置管理员密码。单盘选择“使用目录”，无需创建专用挂载。
4. 如需 systemd，先停止直接运行的平台 JVM，再用同一 JAR 执行 `--install-service deployment-ops`。安装器读取已有目录选择并固定 JDK/JAR 路径；这不会停止业务容器。
5. 在镜像页导入签名 `.ops.zip` 并核对发行方 SHA-256，在部署向导选择目标、查看协议、填写服务地址/端口/账号密码，预检后确认部署。已有介质可用 `--import-package PATH SHA256`，仍执行完整校验。
6. 在应用详情查看 24 个组件、实际健康、日志与资源。升级、回滚、备份恢复及独立挂载策略详见 `JDK-OPERATIONS.md`。
