真实操作包括：发现已有镜像和运行/停止状态的容器；创建独立测试卷和容器；设置 UID:GID、CPU/内存；读取真实日志和指标；镜像引用保护；幂等提交；管理端和代理停止时测试工作负载继续运行；管理服务重启后账本保留；删除容器后原文件仍可从保留卷读取；镜像导出、删除、带 SHA-256 重新导入恢复相同 Image ID 与标签；添加标签及操作审计。

隔离故障包括：启动 API 接受后入口命令失败，记录 FAILED；实际只读节点拒绝审批写入；代理退出显示失联而非旧正常状态；代理重连恢复真实资源；不可达仓库的实际拉取失败记录 FAILED。未使用模拟值替代以上运行结果。

## 原有环境保护

开发前先只读记录基线。开发后再次按原始 ID 核对：

- 原有 20 个容器：ID、状态、启动时间全部保持。
- 原有 28 个镜像：全部 ID 保留。
- 原有 81 个卷：全部名称保留。
- 原有 16 个网络：全部 ID 保留。

只修改新建 QA 资源。验收结束后测试容器已通过审批操作删除，QA 管理端和代理已停止；保留测试数据卷、管理数据库、构建镜像和交付包供审查。不执行生产 daemon 重启、global prune、业务资源强制删除、业务卷清理或业务网络变更。

另创建有内存/CPU/PID 限额、无外网的新 DinD 容器，其 daemon 数据和 socket 均位于本次新建的 QA 目录，不挂载生产 Docker Socket、宿主网络或 PID namespace。空缓存导入包后只启动两个管理容器，独立登录、发现和读写管理数据成功；冷备份后写入额外记录，恢复到新卷后该额外记录消失、备份时记录保留，证明恢复了真实数据。重复新安装被拒绝；仅重启此隔离 daemon 后，管理数据和服务继续可用。隔离测试共 6 项通过，结束时仅停止和删除该新建 DinD 容器。

## 未验收和后续范围

- 第二台物理主机、证书轮换与多物理节点故障尚未验收。
- 已验收空缓存隔离 Docker daemon 的离线冷安装和管理数据备份恢复；物理新机安装、跨版本管理平台升级仍未验收。
- 未在生产服务器制造磁盘不足、重启生产 daemon 或执行整机断网。
- 通用 Compose 编辑/发布、应用定义、配置差异及跨版本回滚属于后续 P1；原签名包安装能力不等于通用 Compose 能力。
- 宿主 Bind Mount、容器终端、批量删除、自动清理、通知渠道及多实例管理端 HA 未开放。持久化历史采样最多保留 7 天，容器后台采样每轮最多 128 个运行容器。

以上边界必须保留在交付说明中，不能据此宣称整个任务书全部验收完成。
