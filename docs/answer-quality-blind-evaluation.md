# 回答质量盲测规范

盲测数据必须来自已脱敏的真实客户问题。评审输入只展示随机换位后的候选 A/B，不能包含产品名、版本号、模型名或生成时间。候选可以来自当前版本、旧版本或外部主流产品。

每条样本保存以下字段：

```json
{
  "id": "stable-anonymous-id",
  "question": "客户原始问题（脱敏后）",
  "evidence": ["评审可核验的内部文档、数据库结果或网页快照"],
  "candidateA": {"id": "current", "answer": "...", "latencyMs": 1200},
  "candidateB": {"id": "baseline", "answer": "...", "latencyMs": 900}
}
```

评审分别给两份回答的 `correctness`、`completeness`、`citationAccuracy`、`directUsefulness` 打 0 到 1 分，并提供简短理由。延迟由系统采集，不交给评审打分，也不混入质量总分。至少两名评审独立评分；出现胜负不一致或任一维度相差 0.3 以上时，进入第三人复核。

建议按租户和问题类型分层抽样，保留困难问题、证据冲突、证据不足、跨文档、数据库聚合和时效网页问题。报告必须同时列出各维度均值、胜率、平局率、P50/P95 延迟和样本数，禁止只展示综合均值。

Java 侧使用 `BlindAnswerPairEvaluator` 执行匿名换位、分数回映射和汇总。真实客户集不得提交到公开仓库，应存放在租户隔离的评测数据存储中。
