# 分析报告正文归属

分析报告的完整正文必须由模型自由撰写并直接返回 Markdown。证据治理不能要求撰写模型同时填报 findings/driverReview JSON，更不能把模型分析退化为 Runtime 逐字段拼装的数据说明。

- 新请求的交付物是完整 Markdown；旧协议的 `reportMarkdown` 仅作兼容解包。claims、数据目录和引用绑定是独立的证据与审计元数据，不预先视为已发布结论。
- Runtime 可以审计证据、保留计算数据、记录覆盖状态及展示独立的状态提示，不能从这些字段重新组织报告正文。
- 模型正文缺失、格式异常或超出长度限制时，复用已有证据请求模型补写；补写失败则返回生成失败状态，不拼接 claims、Worker/Reducer 报告或原始数据附录。
- 聊天页和外置报告只展示交付正文。旧协议、缺少正文或旧 `COMPOSED_BLOCKS` 标记都不构成模板回退的例外。
- 格式检查与证据审计不等同于语义正确性认证。报告组织、业务解释、限定语和结论强度由模型负责。
- Runtime OS 不硬编码业务领域、客户身份、指标含义、会计或计量口径、行业策略与结论。业务语义来自用户问题、角色配置和生产方声明的元数据；同名字段或数值相等不能代替语义声明。
- 最终撰写输入保留模型分析及生产方语义，而不是只传 claim 目录。受预算约束的节选必须显式标记截断与遗漏；模型不能把节选当成全量证据。

回归测试需覆盖：原稿保留、缺失正文后的模型补写、补写失败不拼接、证据元数据保留、前端及外置报告不使用 blocks 替代正文。
