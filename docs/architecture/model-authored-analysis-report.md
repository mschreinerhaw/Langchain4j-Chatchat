# 分析报告正文归属

分析报告的完整正文必须由模型撰写并直接返回 Markdown。证据治理不能要求撰写模型同时填报 findings/driverReview JSON，更不能把模型分析退化为 Runtime 逐字段拼装的数据说明。

- 新请求的交付物是完整 Markdown；旧协议的 `reportMarkdown` 只作兼容解包。claims、数据目录和引用绑定是独立的证据与审计元数据，不预先视为已发布结论。
- Runtime 可以审计证据、保留计算数据、记录覆盖状态及展示独立的状态提示，不能从这些字段重新组织报告正文。
- 模型正文缺失、格式异常或超出长度限制时，复用已有证据请求模型补写；补写失败则返回生成失败状态，不拼接 claims、Worker/Reducer 报告或原始数据附录。
- 聊天页和外置报告只展示交付正文。旧协议、缺少正文或旧 `COMPOSED_BLOCKS` 标记都不构成模板回退的例外。
- 格式检查与证据审计不等同于语义正确性认证。报告组织、业务解释、限定语和结论强度由模型负责。
- Runtime OS 不硬编码业务领域、客户身份、指标含义、会计或计量口径、行业策略与结论。业务语义来自用户问题、角色配置和生产方声明的元数据；同名字段或数值相等不能代替语义声明。
- 最终撰写输入保留模型分析及生产方语义，而不只传 claim 目录。受预算约束的节选必须显式标记截断与遗漏；模型不能把节选当成全量证据。

## 自由撰写的逻辑秩序

自由撰写是表现形式自由，不是事实和推理自由。模型可以自行选择标题、章节、表格和叙事深度，但必须在内部遵循统一的推理顺序：确定决策问题和证据范围，统一指标定义、单位、期间、总体及计量基础，形成观察和计算，再给出有边界的解释、含义、行动与限制。

每项重要判断必须能够追溯为“结论—证据—推理—边界或业务含义”的链条。同一指标在全文使用同一口径和数值；摘要只能压缩正文，不能扩大或强化正文判断；正文必须支撑摘要。因果、意图和持续性行为只有在证据足够时才能作为结论，否则必须标成假设或观察期内现象。建议必须来源于前文发现并说明成立条件。

模型返回前应静默检查全文中的矛盾、无证据推理跳跃、重复结论、范围缺失、算术不一致和段落衔接，并先完成修正。该检查是模型生成约束，不是固定报告提纲，也不能作为 Runtime 拼装业务正文的依据。

## 动态结构与报告质量

最终撰写入口保留 `adaptiveAnalysisPrompt.output`，按其顺序提供 H2 章节指导，标题使用用户语言和业务语境。用户明确指定的格式优先；模型可合并重复章节、略去无内容章节。角色职责和具体业务分析问题由配置角色与生产方声明的语义生成，不靠 Runtime 根据字段名推定行业口径。

最终归纳提示词使用“事实—结构或比较—解释—业务含义—条件性行动”的正向指导，报告正文与审计表单分离。Markdown 表格可以直接使用现有图形分析和多数据集比较功能，无需计算目录中的 `dataRef`。已验证分类数据支持 `COMPARE` 柱状对比；缺少时间维度或完整总体时，仍不自动转成趋势或占比图。

发布前只移除与已知内部提示语完全匹配的独立行；保留代码块、混合业务句子和正常正文，纯协议或清理后为空的输出仍进入原有模型补写流程。清理行为记录为 `analysisReportSanitized`，不代表事实或语义已通过认证。表格转换保留重复、空表头的列位置，超出 JavaScript 安全数值范围的值保留为文本并不参与数值轴选择。

回归测试需要覆盖：原稿保留、缺失正文后的模型补写、补写失败不拼接、证据元数据保留、所有最终生成入口接收一致性规则，以及前端和外置报告不使用 blocks 替代正文。
