# 分析报告正文归属

分析报告的完整正文必须由模型撰写并直接返回 Markdown。证据治理不能要求撰写模型同时填报 findings/driverReview JSON，更不能把模型分析退化为 Runtime 逐字段拼装的数据说明。

- 新请求的交付物是完整 Markdown；旧协议的 `reportMarkdown` 只作兼容解包。claims、数据目录和引用绑定是独立的证据与审计元数据，不预先视为已发布结论。
- Runtime 可以审计证据、保留计算数据、记录覆盖状态及展示独立的状态提示，不能从这些字段重新组织报告正文。
- 模型正文缺失、格式异常或超出长度限制时，复用已有证据请求模型补写；补写失败则返回生成失败状态，不拼接 claims、Worker/Reducer 报告或原始数据附录。
- 聊天页和外置报告只展示交付正文。旧协议、缺少正文或旧 `COMPOSED_BLOCKS` 标记都不构成模板回退的例外。
- 格式检查与证据审计不等同于语义正确性认证。报告组织、业务解释、限定语和结论强度由模型负责。
- Runtime OS 不硬编码客户身份、指标含义、会计或计量口径、行业策略与结论。可选金融脚手架只提供分析问题和章节；业务语义仍来自用户问题、角色配置和生产方声明的元数据，同名字段或数值相等不能代替语义声明。
- 最终撰写输入保留模型分析及生产方语义，而不只传 claim 目录。受预算约束的节选必须显式标记截断与遗漏；模型不能把节选当成全量证据。

## 自由撰写的逻辑秩序

自由撰写是表现形式自由，不是事实和推理自由。模型可以自行选择标题、章节、表格和叙事深度，但必须在内部遵循统一的推理顺序：确定决策问题和证据范围，统一指标定义、单位、期间、总体及计量基础，形成观察和计算，再给出有边界的解释、含义、行动与限制。

每项重要判断必须能够追溯为“结论—证据—推理—边界或业务含义”的链条。同一指标在全文使用同一口径和数值；摘要只能压缩正文，不能扩大或强化正文判断；正文必须支撑摘要。因果、意图和持续性行为只有在证据足够时才能作为结论，否则必须标成假设或观察期内现象。建议必须来源于前文发现并说明成立条件。

模型返回前应静默检查全文中的矛盾、无证据推理跳跃、重复结论、范围缺失、算术不一致和段落衔接，并先完成修正。该检查是模型生成约束，不是固定报告提纲，也不能作为 Runtime 拼装业务正文的依据。

## 动态结构与报告质量

最终撰写入口保留 `adaptiveAnalysisPrompt.output`，按其顺序提供 H2 章节指导，标题使用用户语言和业务语境。用户明确指定的格式优先；模型可合并重复章节、略去无内容章节。角色职责和具体业务分析问题由配置角色与生产方声明的语义生成，不靠 Runtime 根据字段名推定行业口径。

最终归纳提示词使用“事实—结构或比较—解释—业务含义—条件性行动”的正向指导，报告正文与审计表单分离。Markdown 表格可以直接使用现有图形分析和多数据集比较功能，无需计算目录中的 `dataRef`。已验证分类数据支持 `COMPARE` 柱状对比；缺少时间维度或完整总体时，仍不自动转成趋势或占比图。

发布前只移除与已知内部提示语完全匹配的独立行；保留代码块、混合业务句子和正常正文，纯协议或清理后为空的输出仍进入原有模型补写流程。清理行为记录为 `analysisReportSanitized`，不代表事实或语义已通过认证。表格转换保留重复、空表头的列位置，超出 JavaScript 安全数值范围的值保留为文本并不参与数值轴选择。

回归测试需要覆盖：原稿保留、缺失正文后的模型补写、补写失败不拼接、证据元数据保留、所有最终生成入口接收一致性规则，以及前端和外置报告不使用 blocks 替代正文。

## 四阶段整改交付（2026-09-07）

领域脚手架后续已改为按分析类型动态加载数据库 Profile，金融视角及业务章节不再写在 Java 中。维护规则及接口见 [数据库领域分析 Profile](database-domain-analysis-profiles.md)。

1. 新生成及旧提示词兼容入口统一输出 Markdown，不要求模型逐 Claim 填写审计数组。v4 解码仅用于历史结果兼容。
2. 动态提示词增加可选金融资产／交易脚手架和 `sectionTitles`，覆盖资产总览、持仓盈亏、配置集中度、交易结构及后续关注。未匹配金融语境时使用通用分析框架。章节与方法不授予会计定义或事实权威。
3. `ReportComposer.auditVisualizations` 接收正文中的 `visualizationSpec`，由 `ReportVisualizationAudit` 核验后输出统一 v2 图表。聊天页与外置报告共用 `ReportMarkdown`，在原正文位置渲染折线、柱状、饼图、散点与指标卡。原有表格图形分析入口保留。
4. 图表按本次执行的类型化数据核对实体、字段和值，声明的 SUM、AVG、COUNT、SHARE 由 Java BigDecimal 重算。正文另记录数字匹配审计；不可把数字命中当成事实认证。新增后端拒绝用例与 UI Artifact 混排场景，覆盖局部降级及桌面／手机布局。

### 图表声明

模型可在 Markdown 中使用以下 JSON 代码块。`sourceRef` 由运行时提供，不能猜测；优先使用已有计算目录的 `dataRef`。`dataset.rows` 可省略，后端从源数据填入；如模型提供行，实体、字段和值必须一起匹配，重复使用同一条记录会被拒绝。

```json
{"visualizationSpec":{"schemaVersion":"visualization_spec.v2","chartType":"bar","title":"返回样本对比","dataset":{"sourceRef":"运行时提供的引用","xKey":"分类","series":[{"name":"金额","yKey":"金额"}]}}}
```

可选 `transform` 放在 `visualizationSpec` 内：`{"operation":"SUM","groupBy":"分类","metric":"金额"}`，此时 `xKey` 为分类字段、系列 `yKey` 为 `value`。AVG 按分组行数求均值；COUNT 统计行数；SHARE 将分组和除以本次返回记录总和并乘100，分母必须为正且输入非负。AVG/SHARE 保留8位小数、HALF_UP 舍入。被截断的投影不能用于这些聚合；返回记录完整也不证明业务总体完整，页面显示返回样本范围。

折线要求至少两个严格递增的 ISO 日期；散点要求数值坐标；饼图要求单指标、分类唯一、非负且总和非零；指标卡要求一个值。缺失值不补零，超安全数值范围或异常指数不进入图表。任意 ECharts 代码和未声明选项不会传给渲染器。

每次至多捕获12个成功数据集，每集120行、20个标量字段、约16000字符；图表目录入模总预算32000字符，提供投影行数及目录遗漏数。每篇最多6个图表。局部核验失败显示状态提示；能定位源数据时附原始记录表（最多20行、8列），不展示模型伪造的行或未经许可的派生值，不扣留整篇正文。

### 聚合语义与意图编译（后续整改）

生产方在数据集 `analysisContext.reportMetricPolicies` 声明逐指标语义。它与数据库领域 Profile 分工不同：Profile 维护分析方法和章节，生产方元数据维护当前数据集的字段单位及计算许可。不能用领域 Profile 推定具体指标可加总。

```json
{
  "reportMetricPolicies": {
    "金额": {
      "unit": "元",
      "preAggregated": false,
      "allowedOperations": ["SUM", "AVG", "COUNT", "SHARE"]
    }
  }
}
```

仅显式 `preAggregated:false` 且操作位于许可列表的指标可进行派生聚合；缺失语义、未知指标、已聚合指标和不完整投影均拒绝。COUNT 统计返回行数，同样需要指定指标并授予许可，不推定为交易笔数或总体数量。已聚合数据仍可直接绘图；不要为绕过校验把 SQL 汇总结果标记为原始记录。当前采用保守策略，不支持对已聚合的可加指标再次求和或加权平均。

成功捕获数据集时保存语义快照，最终报告中的 `metricPolicies` 或其他同名声明不能授予权限。许可来源仍须由数据生产方准确声明，Runtime 不解析 SQL 来证明声明真实性。未接入该元数据的生产方可继续直接绘图，派生图表会降级为原始表。

单位来自生产方；同图已知单位不一致或模型声明单位与来源不一致时拒绝。SUM/AVG 保留单位，COUNT 为“条”，SHARE 为百分比；缺失单位不推断。此检查不等于完成汇率换算、会计口径或所有时间粒度检查。

模型也可使用更短的意图声明，后端统一编译为已核验的 `visualization_spec.v2`，前端不直接执行原始意图：

```json:visualization
{"intent":"ranking","datasetRef":"运行时提供的引用","x":"分类","y":"金额","title":"返回样本金额排名"}
```

`trend`→折线，`ranking`→按指标降序排列的横向柱图，`comparison`→柱图，`composition`→饼图，`metric`→指标卡，`relationship`→散点图。仍执行原有字段、数值、日期顺序、单指标、精度及行数检查；图表类型不能授予聚合权限。旧 `visualizationSpec.chartType` 入口继续支持。

### 正文事实绑定

`analysisFactBindingAudit` 在发布前检查报告，保持一般自然语言语义为未认证：

- 完整字段的 Markdown 表格按整行比对，包含返回行中的实体、期间、单位、口径等字段，字符串代码保留前导零。命中记录为 `BOUND_SOURCE_ROW`，只证明返回行一致。
- 唯一且完整的来源中不存在对应行时记录 `ROW_BINDING_MISMATCH`，在表格结束处添加局部复核提示。多来源歧义或不完整投影记录 `UNRESOLVED`。缺失源字段、改名表头及嵌套代码示例不强行核验。
- 对“字段为数值／字段:数值”等明确陈述，只有同句包含其余行字段且可定位唯一记录时比对，记录 `EXPLICIT_VALUE_MATCH` 或 `EXPLICIT_VALUE_CONFLICT`。冲突旁添加复核提示；这只是显式值检查，不认证否定、假设、单位换算或因果语义。

表格和正文的冲突不自动改写数字，也不扣留整篇报告。每篇最多120项绑定检查。未识别陈述、合法派生指标以及跨段隐含指代仍需后续业务评测和语义核验；不能将空检查列表理解为全部通过。

### 审计与验证边界

`analysisVisualizationAudit` 记录图表核验结果，`analysisNumericAudit` 记录正文数字在有限证据目录中的命中与未命中，后者只作为复核提示。日期和标题序号不参与普通数字匹配。未命中可能是合法衍生数值或目录截断；命中也不证明单位、实体关系或因果解释正确。这一实现不能承诺自然语言报告绝无幻觉，真实模型质量仍需业务数据评测。

验收运行后端报告／提示词／覆盖测试、前端 `npm run test:ui-artifact`、`npm run test:ui-artifact:visual` 及构建。新增测试覆盖数值篡改、实体交换、重复记录、分母为零、截断聚合、负数饼图、缺失值、伪造目录、异常数值、嵌套代码、乱码格式局部保留及真实聊天页混排。
