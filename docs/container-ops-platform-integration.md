# Live Monitor 容器运维平台接入

本仓库的 `feature/container-ops-platform` 从 `main / 86d496089` 建立。API 前端已通过 package.json / Vue createApp 入口确认是 Vue3，无须换成旧前端。监控平台实现位于独立仓库 `live-monitor-java` 的同名开发分支（基于已核实的 `origin/feature/vue3-frontend / 9222560`）。本次不修改生产分支，不执行生产部署。

## 责任边界

Live Monitor 是部署、主机监控、容器操作、备份、告警和审计的控制面；本仓库继续提供 API/MCP/Node Worker 等业务镜像。两者通过标准部署参数和镜像 Digest 对接，不把 ChatChat 服务名称、服务器 IP、业务数据库、Agent 模型等硬编码到平台业务逻辑中。

现有镜像构建入口 `scripts/application_image_build.py` 与 `deploy/docker/application` 保持原样。继续从干净运行时构建，不以旧业务镜像为基础叠层。构建并推送已验证镜像后，将仓库返回的完整不可变 Digest 登记到平台；平台校验批准仓库、资源限制、Secret 引用、网络、数据卷和健康检查，再经显式授权发布。

## 接入步骤

1. 先在隔离环境构建、测试 Live Monitor（参见该仓库 `docs/container-ops/02-deployment.md`）。为运维用户配置服务器、环境、操作范围授权。不要在 API/MCP 镜像内放 Docker socket 或运维 SSH 密钥。
2. 对每个获批目标主机安装固定命令 SSH Agent，验证服务器公钥，按实际环境配置镜像仓库白名单、只读配置目录和 Secret 文件。平台只保存 Secret 引用。
3. 为各镜像分别登记应用。资源、端口、网络、卷、容器用户、启动 argv、健康检查根据该环境已有部署清单填写，不能从示例端口、名称或某次生产快照推断。
4. 原部署的数据库目录、应用数据和配置不得直接改标签或迁入平台管理卷。先做一致性备份和恢复演练，再审批迁移；平台默认只操作自己标记且应用/环境匹配的容器和卷。
5. API、MCP、Worker 的依赖与网络地址保持现有契约。先确认基础设施和上游服务就绪，再按发布计划逐个部署。该版本提供单应用容器编排，不会自动改写整个已有 Compose 栈。
6. 发布前校验拉取 Digest、网络和参数；输入操作/应用/环境确认后才执行。查看持久任务、SSE 进度、审计和版本历史。失败保留候选、旧容器与原数据；有状态回滚要求明确数据兼容性确认。

## 数据保护

镜像和应用部署配置不是数据库备份。PostgreSQL 使用 pg_dump 自定义格式逻辑备份；卷采用停止全部写入者后的冷备；应用 Secret 在原密钥管理系统单独保全。恢复首先在新卷/隔离数据库验证，再经授权恢复到新目标，禁止覆盖旧库或卷。流量切换及数据库结构回退属于独立变更。

已有业务权限、MCP 模板绑定、任务证据与生产模型配置不因平台接入而修改。生产升级先进入维护状态；平台重新启动有宽限期，避免启动过程产生无效告警。用户主动停止的容器不会被平台自动拉起。

## 登录与入口

保留现有监控入口。新的运维页为 Live Monitor 的 `/#/ops/overview`，通过外部配置或门户链接访问，不能硬编码某台生产服务器 URL。现有嵌入监控令牌仍用于原监控；新增运维拒绝把嵌入令牌自动转换成管理员授权，必须单独交互登录并获得运维范围权限。

生产环境部署、恢复、删除和原数据迁移均需要针对具体变更另行批准。本任务只交付开发分支、可运行构建、隔离测试与接入说明。
