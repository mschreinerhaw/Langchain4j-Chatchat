# 数据探索独立工作空间与角色授权

系统工作空间是应用入口：用户通过左下角账户菜单切换“灵动智策”“数据车间”“数据探索”等空间。数据探索内部的“分析项目”用于组织一次分析的思维链、数据和图表，不再与系统工作空间使用同一名称。

## 授权与兼容

- 在“权限管理 → 角色权限 → 工作空间”中勾选“数据探索访问”，保存后角色成员即可进入；取消后原登录会话的后续请求也会被拒绝。
- 数据探索入口权限为 `workspace:data-exploration:access`。保存工作空间授权时补齐当前账户、菜单和空间目录三个基础权限，不附带其他工作空间、全部 Agent、数据车间或资源管理权限。
- Agent、文档、Skills、MCP 仍遵循原有角色、资源、租户和用户授权。进入工作空间不表示可以读取其他用户的分析项目。
- 原数据车间中的数据探索页面迁入独立空间；一次性迁移为原先可进入数据车间并使用数据探索的有效角色保留入口。迁移标记防止后续重启重新授予已撤销权限。
- 保留现有数据探索 API 路径，服务端同时检查独立空间的启用、许可证和用户授权。伪造工作空间请求头不能绕过检查。
- 数据探索沿用数据车间原有许可证范围；未包含数据车间或数据探索的许可证不开放此空间。
- 旧数据探索链接自动跳转到独立空间，保留分析项目和节点参数。现有项目数据无需改写；显示名称隐藏尾部 UUID。

## 界面

角色权限撤销、资源授权变更及空间设置确认统一使用系统确认弹窗，支持明确确认、取消、Escape 和焦点返回。在确认前不发送权限变更请求。只获数据探索授权的用户不会额外请求对话历史、收藏和任务监控。
