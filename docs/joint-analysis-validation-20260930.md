# Agent 模型继承与联合分析联调

## 范围

用户确认先联调现有自建 Agent：`financial_indicator`、`financial_data_analysis`、`data_asset_operation_management`。部署前注册表只有本地 Agent，没有远程 A2A 服务；因此本轮线上验证是 Runtime 内部 Agent 协作，不宣称已完成外部 A2A 网络互通。远程网关继续执行 SDK 协议回归。

## 架构问题与调整

1. Skill 发布模型、Agent 模型及独立 Skill API 请求模型存在多个来源。现在统一继承调用 Agent 模型，旧 Skill 模型字段不再影响运行；发布页移除模型选择，独立 API 也从已授权 Agent 读取模型。
2. 联合分析入口排除了本地 Agent。现允许发现和选择当前用户有权限的已发布自建 Agent；租户身份、目标 Agent 权限、证据来源权限分别校验，远程证据授权保持独立。
3. 路由把证据来源 Agent 与分析目标 Agent 混为同一标识，无法用一个 Agent 的授权证据交给另一个已授权 Agent 分析。现在目标权限单独解析，取证权限仍由来源范围决定，撤权后调用失败关闭。
4. 既有协作 DAG 没有接入联合分析页面和取证入口。现在复用同一证据获取流程，先执行主分析，复核 Agent 等待前序结论；调用按登记能力和用户选择组成，不根据业务名称或模板标识分支。
5. 部分子任务成功不能显示为全部成功。结果保留任务状态、完成数、参与 Agent、结论与局限，并将协作状态透传到组合工作流和页面。取消信号不当作普通成功结果。
6. 真实取证发现 `operationType=read, runtimeLevel=discovery` 被旧入口误拒绝。按声明支持只读发现级别，同时保留写操作、高风险和禁用工具的拒绝，实际调用仍通过 Tool Runtime。
7. 上游允许 65,536 字符的证据，而本地 Agent 只接受 12,000，导致同一链路协议不一致。新增共享证据预算：每项 65,536、总量 150,000、最多 24 项，本地/远程交接与工具取证采用同一约束；超限拒绝，不截断记录。
8. 文档联合分析复现了执行契约被普通报告综合覆盖的问题：子调用要求 JSON，却被 InterpretationPlan 综合为 Markdown。新增 `EvidenceBoundAgentExecution`，按声明的 `agent_execution_outcome` 契约选择子执行策略，仍由原 `AgentRunLifecycleCoordinator` 持久化开始、完成、失败和取消，模型调用保留期限与用量预算。该策略只使用输入证据，无取数工具，格式错误最多在同一对话修复一次，未知证据引用不能通过。业务报告综合只属于上层，不再改写子 Agent 的输出契约。

## 验证

- 最终构建后端 16 个相关测试类共 100 项通过，包含本地独立授权、撤权、跨租户拒绝、协作依赖、部分失败、输出契约保留、格式修复、虚构引用拒绝、证据预算及 A2A 网关协议测试。
- 前端 3 个测试文件共 56 项通过，覆盖模型继承界面与协作请求构造；Vite 生产构建通过。
- 以上是定向回归，不代替全仓库验证或生产业务质量评测。
- 部署包包含本次构建的前端入口，已核对包内 `static/index.html` 与构建输出一致。
- 生产浏览器验证显示 22 项算力（10 个模型、12 个已授权自建 Agent），协作复核控件正常。Skill 发布配置 API 返回 `modelSource=AGENT`，不再返回独立模型选择列表。
- 第一轮真实联合分析在取证前因发现级别被拒绝；第二轮完成取证后因下游证据预算冲突失败，两个依赖任务正确标为 SKIPPED_DEPENDENCY。这两轮均为失败记录，不计作成功验收。
- 文档诊断运行 `2d0776cd-0103-4fc7-9ea0-7a3e7673d6a6` 返回普通报告，被协作契约拒绝；已确认子 Runtime 结算后才准备替换版本。此记录用于验证契约路由缺陷，不算联合分析成功。
- 部署检查另发现 28 条早于本轮的历史 Runtime RUNNING 记录。当前普通任务列表无活动任务，当前部署启动后没有对应的新运行；没有擅自改写这些历史记录。本轮验收不覆盖历史任务修复。

部署与真实联合分析结果将在联调结束后追加。
