# MCP 本地管理账号与登录审计

## 范围

MCP 管理控制台新增用户管理与登录审计入口，使用现有深色导航、Element Plus 表格、筛选和反馈组件。用户管理采用左侧用户列表、右侧账号信息与菜单授权的主从布局。支持创建用户、按名称/状态查询、分页、启停账号、重置密码、逐项授权和保存反馈。所有登录账号均可通过侧栏修改自己的密码。

本地账号只用于 MCP 服务自身的运维控制台。Runtime OS 用户、角色和工具/数据资源授权仍由现有统一权限控制面维护。本次不恢复历史 MCP 业务授权后台，也不修改 MCP 工具执行的业务权限判断。

## 数据与鉴权

- 复用 `mcp_admin_user` 和现有 PBKDF2 密码存储，API 只返回用户概要，不返回散列或密码。
- 新增 `mcp_admin_menu_grant`，每条记录包含用户、菜单、授权人、时间；用户/菜单组合唯一。PostgreSQL 增量脚本为 `chatchat-mcp-server/src/main/resources/admin/mcp-admin-menu-grants.sql`。
- 复用服务端 `McpAdminMenuCatalog` 中的业务导航模块，另提供用户管理、登录审计和 License 管理权限。授权粒度为整个管理菜单模块，包括该模块的接口操作。
- 新用户默认没有菜单权限。内置 `admin` 保留所有管理权限，不能通过用户管理停用或变更授权；本人可修改密码。内部通信身份仍用于既有服务链路，不进入普通用户创建流程。
- 新增过滤器在现有登录校验后、License 校验前读取当前账号与数据库菜单授权，阻止未授权的直接 API 读写；未登记的管理接口对普通账号默认拒绝。
- 用户管理与登录审计属于基础安全能力，不依赖业务 License；业务菜单必须同时满足用户授权和原有 License 条件。
- 撤销菜单授权对已有会话的下一次请求生效。停用、重置密码与本人修改密码会撤销该账号的会话，不影响其他用户。
- 用户更新在数据库中锁定对应账号行；授权更新、账号信息更新和操作记录共同提交。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/users` | 用户查询与分页 |
| `POST /api/v1/admin/users` | 创建本地用户，默认不授予菜单 |
| `GET /api/v1/admin/users/menu-catalog` | 本地可授权菜单目录 |
| `PUT /api/v1/admin/users/{username}` | 保存状态、菜单权限和可选的新密码 |
| `GET /api/v1/admin/auth/me` | 当前用户与可用菜单权限 |
| `POST /api/v1/admin/auth/password` | 本人修改密码，复用既有实现 |
| `GET /api/v1/admin/login-audits` | 按关键字、结果查询登录日志，复用既有实现 |

登录审计复用 `mcp_login_audit_log`，保留历史数据，展示时间、用户名、结果、来源 IP、终端和失败原因。创建、修改授权和重置密码记录在同一审计存储中，使用独立 action；登录页面仅展示 `admin-login` 记录。用户不提供物理删除入口，停用后保留账号及审计关系。

## 发布与回滚

仅替换 MCP 应用镜像，不更换 API 镜像。发布脚本 `scripts/deploy-mcp-local-admin.py` 先验证制品、备份 MCP 数据库与部署配置，记录原镜像 ID/制品 SHA，再执行增量建表、启动和业务授权指纹核验。服务端备份文件包含敏感账号数据，保留在私有目录。

发布失败时恢复原镜像与部署配置，新建表可保留，不删除原有数据。若已投入使用后主动降级，应先停用此次新增的普通本地账号：旧版本没有按用户菜单授权的隔离能力。导出菜单授权后再按需归档新表；恢复时使用本次备份并先核对期间新增的登录审计及账号变更，不能直接覆盖后续生产数据。Git 使用独立功能提交和发布记录，既有基线 Tag 保持不变。
