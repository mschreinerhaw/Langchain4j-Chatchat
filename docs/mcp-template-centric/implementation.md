# 模板驱动能力发布实施说明

业务工作空间改为“可用模板 / 我的发布 / Agent 工具”。用户只选择有权使用的模板；平台自动固定资产、执行器、参数 Schema 与配置指纹。我的发布默认显示运行中版本，Agent 页面允许解除已下线工具的绑定。历史发布管理仅开放给具有统一权限中心管理权限的管理员。

MCP 运维控制台保留现有资产及模板维护能力，按资产、API、Python、查询模板与运行诊断组织入口。本地运维账号管理、登录审计及 License 移入当前用户折叠卡片。业务身份、资源授权仍以 API 为权威，本地运维账号不能调用模板发布控制面。

## 权限和调用

- 新增 `TEMPLATE` 资源类型，权限中心中作为“业务模板”分类。模板授权与资产操作权限取交集；发布只增加该用户的业务工具所有者授权，不增加底层资产权限。
- 发布复用 `mcp_tool_release`，使用 `TEMPLATE_CAPABILITY` 类型，按租户、发布者、模板及资产生成稳定工具名。同一版本重复请求幂等；PostgreSQL 事务咨询锁和现有唯一约束串行化版本创建。失败重试会重新协调工具注册。
- 发布保存 Schema、执行器、固定参数和依赖配置指纹。依赖变更、停用或环境下线会使旧版本不可调用，必须重新确认发布。使用量和更新时间不作为版本变化，参数 Schema 中的同名业务字段仍参与指纹。
- API 签名用户、租户、Agent 身份；模型参数和请求头不能替换签名身份。签名密钥缺失、签名过期或权限服务不可用时拒绝。私有 gRPC 通道继续使用既有内部凭据认证。
- `tools/list` 和 `tools/call` 使用相同的实时策略：有效发布、当前模板和资产权限、当前用户工具授权、已发布 Agent、明确工具绑定。内部注册目录使用单独认证的服务器请求；其全量目录不作为业务用户的工具清单。
- 解绑、下线和授权撤销在下一次调用重新校验；已经开始执行的操作不作事务撤销。服务范围或前缀选择不会自动把新模板工具加入 Agent。
- API、HTTP、SSH、SQL、Python 与远端 MCP 工作流继续复用已有实现。固定目标使用进程内类型传递，普通 JSON 不能伪造；实际执行仍检查启用状态、资产权限和原有安全策略。SQL 继续遵守只读执行策略，HTTP/API 按方法区分只读与写入权限，SSH 按模板风险区分操作级别，Python 要求执行权限。
- 审计关联发布版本、用户、Agent、工具和结果，不保留签名证明或连接凭据。业务参数遵守管理员维护的 Schema、原执行器参数校验与数据源边界；不通过授权模板扩大数据库账号本身的访问范围。

## 增量迁移和兼容

不删表、删列或历史发布。应用启动时对已启用的 SUPER_ADMIN 角色一次性初始化新 TEMPLATE 类型默认授权，并持久化迁移标记；之后撤销不会因重启恢复。普通用户默认没有模板授权。其他现有授权保持原值。

旧 Agent 的业务工具名称、固定模板检索绑定和执行工作流保留。旧发布定义不能由普通发布用户直接修改；管理员仍可在历史管理入口维护。Agent 原有通用工具选择器不展示新模板工具的全局目录，新工具使用模板工作空间的受控分配流程。

## 构建、部署和回滚

后端定向回归覆盖 19 个测试类、102 项测试；前端相关 5 个测试文件、45 项测试通过。API 和 MCP 前端构建通过。后端改造已通过完整 Java JAR 部署；最后的页面修正仅替换构建出的静态资源，并逐项核对其余 JAR 条目内容保持一致。生成静态资产由构建产生，不混入业务源代码提交。

`scripts/deploy-template-capabilities.py` 核对运行包基线与候选包 SHA-256，使用干净运行时构建镜像，在停止应用之前检查活动任务并备份数据库、当前 JAR 和部署配置。保留服务器运行配置和密钥挂载。启动后验证原有授权不变，新授权只能是 SUPER_ADMIN 的 TEMPLATE 默认值。

异常时恢复原镜像与部署配置，保留历史数据。人工回滚到旧应用前应先将 `TEMPLATE_CAPABILITY` 的运行版本下线；保留不可变定义、审计记录及新权限迁移标记。禁止通过回滚数据库覆盖升级后产生的有效业务记录。

生产验收见 [production-verification.md](production-verification.md)，包含实际 MCP 调用、浏览器检查及测试对象清理后的授权对账。
