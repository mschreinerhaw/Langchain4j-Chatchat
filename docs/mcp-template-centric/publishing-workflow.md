# MCP 动态模板查询工具发布

## 功能定义

沿用主分支 `template_query` 动态发布的业务模型：管理员创建一个具名 MCP 查询工具，绑定父级检索能力、授权角色以及多个可查询的子模板。发布的是这个受控集合。该工具返回集合内仍处于启用且权限有效的模板元数据与参数契约，底层执行器保持现有职责。

此前增加的逐模板发布界面偏离了这个需求，已从主入口移除并删除对应前端组件。原有动态集合查询功能恢复为主页面，不再称为历史功能。既有数据、版本记录和内部兼容接口保留。

## 操作路径

1. 进入 MCP 工具发布，默认查看运行中的动态查询工具。按父级执行能力分类、名称和版本状态筛选，按工具分页查看。
2. 点击“新建 MCP 工具”，填写业务名称、说明和稳定的逻辑名称。
3. 选择执行能力和授权角色。平台读取该角色在此父级能力下可用的子模板。
4. 按业务分类、关键词和分页勾选多个子模板。跨分类和分页保留选择，支持选择本页、清空已选和查看完整已选集合。
5. 保存草稿，校验定义，再运行合约测试。校验通过后直接进入测试页，测试通过后回到概览执行发布。
6. 发布为 `<逻辑名称>_template_query`，供 Agent 选择该集合能力。沿用现有子能力委托父级检索链路；查询范围由已勾选集合与实时权限共同约束。

## 状态和权限

Agent 工具选择和 MCP 能力页共用服务端“已发布业务工具目录”：只返回本租户运行中的集合工具，并校验角色与 MCP 工具资源权限。底层注册表中的检索父工具、SQL/SSH/Python 执行器和未发布、已下线工具不进入该目录。目录不可用时显示错误，不回退到全部注册工具。

发布配置新增“业务分类”，由管理员按工具用途填写，随版本保存。Agent 和 MCP 能力页均按此字段筛选；不再使用后端类型作为用户分类。原有版本无分类时显示“待分类”，不根据名称猜测业务。分类变更沿用创建新版本流程。

Agent 新增工具绑定会在服务端再次检查，包括工具配置、调用步骤、服务整组绑定和前缀绑定。已有 Agent 的历史设置允许原样保留，新选择只能来自当前有权使用的已发布目录。原有工具执行和每次调用的权限检查保持生效。

- 运行中、待完成发布、已下线分开查看。待完成包括草稿、已校验、测试通过，详情显示当前下一步。
- 发布版本保持不可变，修改集合创建下一版本，支持已有版本回滚。
- 沿用现有管理权限、租户隔离、角色授权、模板启用和调用校验。本次 UI 修正不扩大管理或运行权限。
- MCP 管理端继续维护 API 等子模板，并可通过 `VITE_WORKSPACE_URL` 配置的链接进入查询工具发布页面。创建子模板与发布查询集合有不同入口和说明。

## 验证范围

前端回归覆盖主路由直接打开集合发布、跨页与分类保留多个选择、单个工具持久化多个 templateKeys、切换角色或父能力清空选择、校验测试的下一步操作、版本不可变和过期目录响应。真实场景使用临时查询工具验证多个已授权子模板组成一个集合，测试和发布后的父级委托查询均不超出集合；验收工具最终下线并保留审计记录。

目录接口继续返回授权范围内的完整目录，前端负责分类筛选和分页，不改动模板检索的运行时分页语义。
