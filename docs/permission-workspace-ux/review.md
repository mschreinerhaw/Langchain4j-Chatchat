# 权限管理工作空间信息架构与交互重构

开发分支 `feature/unified-management-workspaces`，起点 `9c4679ab6`。保留已有基线及 2.1.0-rc1 发布 Tag。

## 现状审查

| 现有入口 | 实现与问题 | 整改 |
| --- | --- | --- |
| 系统管理 → 用户/组织/角色 | 共用 `SystemManagementView`，四张统计卡反复占位；初始租户选数组第一项而非当前身份租户 | 复用账户/组织 CRUD，统一紧凑布局、搜索和分页，修正身份上下文 |
| 资源授权 | `ResourceAuthorizationPanel` 先选角色再选 Agent，才能操作工具/文档/技能；与工具授权页重叠 | 合并为统一资源视图，以资源为入口，可反查角色和用户 |
| 技能权限 | `SkillRoleAuthorizationPanel` 提供单独双向查询，产生第三层菜单和额外滚动 | 删除专用页面，将查询能力归入统一角色/资源视图 |
| 工具与数据授权 | `PermissionToolsView` 单独技术配置表单，暴露工具编码及范围表达式 | 合并资源授权，业务列表先展示名称/动作/来源/范围，技术字段放详情 |
| 登录审计 | 原有分页登录审计 | 统一安全审计入口，同时提供授权变更记录 |
| 工作空间 | 页面和 `workspaces` 菜单均存在，需检查菜单权限绑定和展示路径 | 平台管理恢复“工作空间设置”，继续使用 `WorkspaceService` |

权限唯一权威仍为 API PostgreSQL 的 `sys_role_permission`、`resource_grant`、`mcp_tool_permission` 及关联身份表。复用现有授权写接口、Runtime/MCP 校验和审计；只扩展统一目录投影，不新增权限存储或并行授权引擎。

## 新导航

权限管理 → 用户管理 / 组织管理 / 角色权限 / 资源授权 / 安全审计（五个平级页面）。全局 Sidebar 不再保留系统管理嵌套和独立技能、工具授权入口。旧地址归一到对应的新入口，保留路由选中状态及面包屑。

角色列表与授权详情主从布局，共享资源编辑器按工作空间、功能操作、工具、数据源、知识库及其他资源分组。资源授权复用同一编辑能力，反查直接角色/用户及租户继承规则。后端没有角色层级继承模型，不伪造角色继承；展示真实租户/角色/用户来源及拒绝规则。数据源范围沿用工具执行范围，不把页面筛选当作新增访问授权。
