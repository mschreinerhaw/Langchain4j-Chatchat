## 镜像膨胀分析与修复

历史部署以旧业务镜像为 `FROM` 并重复 `COPY app.jar`。API 镜像中每次增加约 430 MB 的不可变 JAR 层，最终达到 33,297,440,048 字节。MCP 同样累积多个旧 JAR 层。覆盖或删除容器内 JAR 不能移除历史镜像层。

本次使用不含业务 JAR 的 Java 基础层重新构建，保留 SQL Studio 的 Python/SQLGlot 与 MCP 的 Docker CLI。每个应用镜像只有一个业务 JAR 层。

| 服务 | 升级前镜像大小 | 本版镜像大小 | 结果 |
| --- | ---: | ---: | --- |
| API | 33,297,440,048 B（约 33.30 GB） | 743,629,850 B（约 743.63 MB） | 减少约 97.8% |
| MCP | 2,347,295,129 B（约 2.35 GB） | 583,985,564 B（约 583.99 MB） | 减少约 75.1% |
| News | 417,654,916 B | 417,683,352 B | 正常单 JAR 镜像 |

这些是镜像显示的未压缩大小；共享层不能重复计入真实磁盘占用。

## 部署与回滚保障

- API、MCP、News 和 node-proxy 已切换；保留原 Compose 项目、配置值及持久化挂载。
- 数据库、OpenSearch、Redis、对象存储、网关和原 Coding Agent 容器保持原实例。
- 备份 API/MCP PostgreSQL、原始 API/MCP JAR、原配置，并在关闭 API 单写进程后备份 RocksDB 和 UI 产物。私有备份约 927 MiB，位于服务器本版 `private-backup/`。
- 精简回滚镜像 API 约 743.61 MB、MCP 约 583.97 MB；回滚不依赖已清理的旧叠加镜像。
- 已检查回滚镜像构建与大小；本次没有在业务验收后再次执行实际在线回滚演练。

清理 88 个未引用的旧业务镜像标签及可识别的闲置业务镜像，保留所有容器引用、当前版本和精简回滚镜像。旧镜像层仍被 BuildKit 引用，因此在确认活动构建缓存为零后清理闲置构建缓存，Docker 报告回收 **37.86 GB**。
