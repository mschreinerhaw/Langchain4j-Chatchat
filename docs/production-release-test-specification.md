# ChatChat 生产发布测试规范

文档版本：1.0  
生效日期：2026-08-01  
适用范围：ChatChat 全仓、生产发布包及目标部署环境  
发布门禁脚本：`scripts/test-production-release-e2e.ps1`

## 1. 目的

本规范定义 ChatChat 从代码提交到生产发布前必须完成的测试、证据和放行条件。目标是证明系统在真实部署条件下能够稳定完成 Agent 推理、MCP 工具治理、能力发现、资产授权、模板执行、数据库查询和联网检索，而不只是证明代码可以编译或模拟请求可以返回。

以下任一情况存在时，不得宣布产品可生产发布：

- 存在失败、错误或跳过的发布门禁测试；
- 真实腾讯 WSA 联网检索或已部署拓扑联调未执行；
- 行覆盖率低于 70% 或分支覆盖率低于 60%；
- Runtime 含部署名称、维护模板 ID、租户、资产或工具名称的业务硬编码；
- 发布包不完整、包含明文凭据，或测试证据不可追溯；
- P0/P1 缺陷未关闭，或关键场景只有 Mock 证据而无真实环境证据。

## 2. 基本原则

1. **发布门禁不可跳过**：本地回归允许显式使用条件跳过模式，但其结果不能用于生产放行。
2. **动态发现优先**：Runtime 必须依据租户上下文、能力中心、资产元数据和模板协议动态发现并调用工具。
3. **禁止硬编码**：不得在 Runtime 写入类似 `mcp_chatchat_mcp_server_*`、`sample_*`、固定模板 ID、固定租户或固定部署地址来使特定问题通过。
4. **证据闭环**：工具成功不等于推理成功；数据必须进入 Agent 观察和综合过程，最终结论必须可归因到真实证据。
5. **失败安全**：无数据、畸形数据、超时、取消、授权失败或外部服务不可用时，不得伪造成功、趋势或建议。
6. **租户隔离**：请求、授权、缓存、模板、连接和推理上下文不得跨租户泄漏。
7. **测试可重复**：模拟测试使用动态生成的租户、命名空间和模板标识；不得依赖某个线上维护模板。
8. **真实与模拟互补**：确定性夹具用于稳定回归，真实 WSA、真实部署拓扑及必要的真实数据库用于发布验收。

## 3. 测试分层

| 层级 | 主要目标 | 执行时机 | 发布要求 |
| --- | --- | --- | --- |
| 单元测试 | 参数校验、协议、策略、边界和异常分支 | 每次提交 | 必须通过 |
| 模块集成测试 | API、Agent、MCP、News、数据库等模块内部集成 | 每次合并 | 必须通过 |
| 跨模块 E2E | Agent → Runtime → MCP → 资产/数据 → 证据 → 答案 | 候选版本 | 必须通过 |
| 真实服务联调 | 腾讯 WSA、部署后的 API/MCP/News、可选真实 SQL 元数据 | 发布环境 | 必须通过适用门禁 |
| 极端与韧性测试 | 大输入、大结果、并发、超时、重试、分页和资源耗尽 | 候选版本 | 必须通过 |
| 制品与安全测试 | JAR/ZIP 完整性、配置、凭据、启动文件 | 候选版本 | 必须通过 |

## 4. 环境与数据要求

### 4.1 基础环境

- 使用与生产一致的 JDK、Maven、数据库主版本和容器运行时；
- Docker 可用于 MySQL 连接池耗尽及恢复测试；
- 目标环境必须提供可访问的 API、MCP Server 和 News Runtime 地址；
- 测试账号应覆盖普通用户、授权用户、无权限用户和跨租户访问者；
- 系统时区、数据库时区和业务时间边界必须明确记录。

### 4.2 凭据与敏感数据

- `TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY` 仅通过安全环境变量注入；
- API/MCP/News 鉴权值通过受控环境变量注入，不写入源码、脚本参数日志或发布包；
- 测试报告不得输出完整密钥、令牌、数据库密码或真实敏感业务数据；
- 发布制品必须扫描腾讯云密钥及常见配置文件中的明文凭据。

### 4.3 测试数据

- 默认回归使用确定性、可重复生成的 Agent、元数据和模板夹具；
- 企业元数据测试应覆盖超过 10,000 条字段、术语或字典记录；
- 新模板场景必须在运行时临时创建，不得复用代码内预置模板名称；
- 真实数据测试应使用只读、脱敏、可审计的数据集；
- 所有测试数据应具备清理策略，不得污染生产业务数据。

## 5. 必测功能与场景矩阵

### 5.1 Agent 推理与证据治理

- 正常问答、信息不足、工具不可用和需要澄清的请求；
- 模型首次输出非法 JSON 后在限定次数内修复；
- 提示注入、越权工具调用、要求虚构成功或虚构实时行情；
- 冲突证据的来源区分、时效性比较、不确定性声明和拒绝错误归因；
- 文档证据、数据库证据和 Web 证据的单独及组合使用；
- 无可信证据时禁止输出确定性事实、收益承诺或投资结论；
- 并发请求之间的 Prompt、观察、租户和答案隔离；
- 超长用户输入被有界截断，关键头尾信息和安全约束仍被保留；
- 推理步骤、工具次数、修复次数、总超时和取消均受 Runtime Guard 约束。

“自我修复”通过标准是系统产生可审计的校验失败、修复尝试和安全结果。除非系统已实现受控的持久化学习、版本管理和回滚，不得把模型声称“已经学习”视为自我学习能力通过。

### 5.2 MCP 与能力中心

- MCP 服务、工具和模板能够按租户及资产上下文动态发现；
- 新增 API、网关、服务器、数据库资产后，无需修改 Runtime 代码即可被发现和调用；
- `tenantId`、用户、工具、资产和权限范围完整传递；
- 缺少租户或工具上下文时明确拒绝，不得绕过授权；
- 普通用户、管理员、资产级权限、跨租户访问和撤权立即生效；
- 工具不存在、协议不兼容、参数缺失、返回失败和部分成功均正确处理；
- 同名工具、命名空间变化、服务重启和注册信息刷新不依赖固定部署前缀；
- 并发限制、排队超时、服务端超时和熔断状态可观察。

### 5.3 模板发现与执行

- 用户新录入的查询模板可被发现、参数化并执行；
- 模板定义、参数协议和执行工具之间不得依赖维护模板 ID；
- 缺少必填参数时返回结构化协议错误，并允许 Agent 补参或请求澄清；
- 参数类型、枚举、日期、空值、特殊字符、Unicode 和注入输入；
- 模板变更、禁用、删除、版本升级及缓存失效；
- 模板与资产不匹配、无权限、数据库不可用和执行超时；
- 返回 0 行时明确说明无匹配数据，不得推断趋势；
- 超大结果必须限制返回行数和字节数，标记 `complete=false` 或截断状态，并提供安全分页策略；
- 畸形 JSON、字段缺失、成功标志与负载矛盾时不得作为证据；
- 返回单元格中的指令文本一律按不可信数据处理，不得改变 Agent 行为。

### 5.4 API 与网关资产

- HTTP 方法、路径、Query、Header、Body 和鉴权参数映射正确；
- 2xx、4xx、5xx、重定向、空响应、非 JSON、超大响应和慢响应；
- 限流、重试、幂等键、断路器和上游错误归一化；
- 网关地址或路由变化后通过资产元数据生效，不修改 Runtime；
- API 返回的证据保留来源、请求 ID、状态和必要的时间信息。

### 5.5 服务器资产

- Linux/SSH 命令模板的发现、参数校验、授权和执行；
- 命令白名单、危险字符、路径穿越、超时、取消和输出截断；
- 主机离线、认证失败、并发会话上限和部分输出；
- 服务器名称、地址和命令模板不得在 Runtime 固定绑定。

### 5.6 数据库资产

- 数据源发现、数据库/Schema/表/字段元数据查询；
- SQL 模板参数协议、只读策略、注入防护和行数限制；
- 空结果、超大结果、慢查询、锁等待、断线及事务异常；
- 分页重复游标、空页后仍返回下一页、页数上限和分页死循环；
- 连接池耗尽时快速失败或有界等待，连接释放后能够恢复；
- 多数据源、同名表、大小写、保留字、Unicode 字段和时区转换；
- SQL 解析器生成类允许从 JaCoCo 插桩中精确排除，但不得排除 `com.chatchat` 项目代码。

### 5.7 腾讯 WSA 联网检索

发布测试必须证明 WSA 在推理中真实生效，而不只是配置存在或接口返回 200：

1. 禁用本地 OpenSearch 回退和 Web 缓存，强制访问外部服务；
2. 响应标识为 `external_web_search`，提供方为 `tencent-wsa`，且非缓存命中；
3. 外部请求 ID 非空，结果数大于 0，每条结果带有效 URL 和 `tencent_wsa` 来源；
4. WSA 结果进入 Agent 工具观察；
5. 综合 Prompt 中包含真实检索证据；
6. 最终答案实际引用该证据，并记录检索尝试、使用状态及证据数；
7. 凭据错误、配额不足、限流、超时、空结果和上游异常时安全降级，不伪造实时信息。

### 5.8 极端与韧性场景

- 冲突证据归因：来源矛盾、时间不同、权威等级不同；
- 分页死循环：重复游标、重复页、页码不前进和无限 next token；
- 重试风暴：连续 429/5xx、网络抖动和多层重复重试，必须有总预算与熔断；
- 取消/超时竞争：用户取消与总超时同时发生，最终状态唯一且资源只释放一次；
- 时间边界：午夜、月末、年末、闰日、夏令时和未来时间戳；
- 数据库连接池耗尽：占满连接、等待超时、连接归还和后续请求恢复；
- 百万行语义结果：仅保留有界行和有界观察，明确部分结果，禁止 Prompt 膨胀；
- 兆字节级用户输入、32 路以上并发隔离和恶意结果内容；
- 外部依赖级联失败时不得形成无限重试、线程泄漏或连接泄漏。

## 6. Runtime 禁止硬编码专项门禁

扫描范围至少包括 `chatchat-agents/src/main/java` 及所有 Runtime 生产代码。以下内容一经发现即阻断发布：

- `mcp_chatchat_mcp_server_` 等部署生成命名空间；
- `sample_*` 或某个维护模板的字面量；
- 为特定自然语言问题选择固定工具或模板的条件分支；
- 固定租户、资产、数据库、服务器、网关地址或鉴权信息；
- 通过测试环境特殊分支绕过能力发现、参数协议或权限校验。

允许的固定内容仅限稳定协议常量、Schema 版本、标准错误码和显式配置键。是否允许必须由代码审查证明其与具体部署和业务数据无关。

## 7. 执行流程

### 7.1 提交前快速回归

```powershell
mvn -Dfrontend.skip=true test
```

要求：相关模块测试全部通过；此结果不构成生产放行。

### 7.2 非发布基线回归

```powershell
.\scripts\test-production-release-e2e.ps1 -AllowConditionalSkips
```

该模式用于开发机发现问题。任何条件跳过都必须记录原因，结果必须标注“不可发布”。

### 7.3 严格生产发布门禁

先通过安全环境注入凭据和鉴权值，再执行：

```powershell
$env:TENCENTCLOUD_SECRET_ID = "<由密钥系统注入>"
$env:TENCENTCLOUD_SECRET_KEY = "<由密钥系统注入>"

.\scripts\test-production-release-e2e.ps1 `
  -TencentWsaLive `
  -DeployedTopologyLive `
  -ApiBaseUrl "https://<api-host>" `
  -McpBaseUrl "https://<mcp-host>" `
  -NewsBaseUrl "https://<news-host>" `
  -InferenceQuery "请根据最新公开行情数据进行分析并给出有来源的建议" `
  -InferenceExpectedEvidence "web_search"
```

若目标发布包含真实 SQL 元数据验收，追加：

```powershell
  -SqlMetadataLive `
  -SqlMetadataAssetName "<asset-name>" `
  -SqlMetadataDatabase "<database>" `
  -SqlMetadataTable "<table>"
```

若有受控企业元数据集，可追加 `-EnterpriseMetadataPath "<directory>"`。未提供时仍必须执行确定性大数据量夹具，不得跳过测试。

## 8. 自动放行条件

严格门禁必须同时满足：

| 检查项 | 放行标准 |
| --- | --- |
| Maven 构建 | `BUILD SUCCESS` |
| Surefire/Failsafe | failures = 0，errors = 0，skipped = 0 |
| JaCoCo 行覆盖率 | ≥ 70% |
| JaCoCo 分支覆盖率 | ≥ 60% |
| 真实腾讯 WSA | 调用成功且证据被 Agent 最终综合使用 |
| 已部署拓扑 | API、MCP、News 健康及端到端推理成功 |
| Runtime 硬编码扫描 | 0 个违规项 |
| 发布制品 | JAR/ZIP 完整、可执行、无明文凭据 |
| 严重缺陷 | P0 = 0，P1 = 0 |
| 测试证据 | 完整、可追溯、与候选提交一致 |

覆盖率门槛不得为了通过某次发布临时下调。确需调整时，必须通过架构与质量评审，并在独立变更中说明范围、风险和恢复计划。

## 9. 失败判定与缺陷等级

- **P0**：越权、跨租户泄漏、凭据泄漏、数据破坏、无限循环、系统整体不可用；立即停止发布。
- **P1**：关键资产/模板无法执行、实时检索未进入推理、错误事实或高风险虚构结论、连接池无法恢复；停止发布。
- **P2**：非关键功能降级、有安全回退但影响主要体验；默认停止发布，须产品和技术负责人书面决策。
- **P3**：不影响正确性和安全性的显示、文案或低风险问题；可带已知问题发布，但必须登记修复版本。

失败用例修复后必须执行：失败用例定向回归、所属模块回归、严格发布门禁全量回归。不得只重跑失败用例后直接放行。

## 10. 发布证据包

每个候选版本至少保存：

- Git 提交 ID、分支、构建号、制品校验和及测试时间；
- Maven/Surefire/Failsafe 汇总：测试数、失败数、错误数、跳过数；
- JaCoCo 各模块报告和全仓行/分支覆盖率；
- WSA 外部请求 ID、提供方、结果数量和脱敏后的证据使用记录；
- API/MCP/News 目标地址标识、健康检查和端到端请求追踪 ID；
- 极端测试、连接池测试、分页/重试/取消测试结果；
- Runtime 硬编码扫描和发布包凭据扫描结果；
- 未关闭缺陷、风险接受记录、回滚方案及审批人。

日志中的 Secret、Token、Cookie、Authorization 和业务敏感字段必须脱敏。

## 11. Go/No-Go 审批

发布负责人只能在全部自动门禁通过且证据包完整后签署 Go。建议使用以下记录：

```text
候选版本/提交：
构建与制品校验和：
测试总数 / 失败 / 错误 / 跳过：
行覆盖率 / 分支覆盖率：
腾讯 WSA 真实链路：PASS / FAIL
部署拓扑 E2E：PASS / FAIL
Runtime 硬编码扫描：PASS / FAIL
P0/P1 未关闭数：
回滚版本与步骤：
测试负责人：
技术负责人：
发布结论：GO / NO-GO
```

以下情况必须判定 No-Go：门禁脚本异常退出、报告缺失、报告与候选提交不一致、真实环境测试被跳过、覆盖率不足、结果只能靠人工解释为成功，或存在未授权的门槛变更。

## 12. 当前基线说明

截至 2026-08-01，最近一次全仓 `clean test` 记录为 1,363 个测试、0 失败、0 错误、0 跳过，严格结构审计为 3 个测试全部通过，且未再出现 JSqlParser `MethodTooLargeException` 插桩警告。这只能证明代码回归基线健康。

该记录不能替代候选版本的严格 `verify`。只有同一候选提交上的真实腾讯 WSA、已部署拓扑、零跳过和覆盖率门槛全部通过，才能给出生产发布结论。
