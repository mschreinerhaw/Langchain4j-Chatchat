# Runtime 分析质量补强

针对日志分析运行中出现的 JSON 字符分片、Worker 重复长报告及结构化洞察缺失，补强以下链路：

- `mcp_analysis_payload.v1.data` 内的 `python_analysis_bridge_result.v1.stdout` 若为 JSON 对象或对象数组，按完整对象投影为单个分析任务。记录保留 `sourcePath`、`recordIndex`、`values`；不同路径不隐式关联或汇总。非 JSON 输出继续走原有路径，原始证据仍供审计使用。
- Worker 只分析当前记录范围，返回简短摘要与结构化发现；提示词明确给出校验器接受的绝对记录引用格式。日志分别记录提出、拒绝及待复核的洞察数量。
- 已通过 Worker 验收的数据可将原始数值绑定到报告指标。数值由 Runtime 复制，附记录引用，不推断单位；确定性计算结果优先进入有容量上限的数据目录。没有语义依据时不凭字段名生成图表或汇总。
- 清理包含内部证据标识的完整行内代码片段，避免只删除标识中间部分留下反引号和路径碎片。这不等于修复或重建原始证据链接。

本轮未改变 Planner、工具结果评审的模型调用策略，也没有提供生产运行提速比例。验收仍需对相同输入记录模型调用次数、各节点耗时、结构化洞察接受率、最终报告数据绑定和图表表现；不能仅凭单元测试宣告完整 Runtime OS 目标达成。
