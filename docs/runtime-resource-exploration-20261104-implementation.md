# Runtime OS 资源探索实施记录

本轮先提交了[源码与实际索引审查报告](runtime-resource-exploration-20261104-audit.md)，再依次实施 P0、P1、P2。分支为 `feature/runtime-knowledge-exploration`。本文件记录实际行为；端到端验收另行记录，不能用单元测试替代真实 Agent 结果。

P0 提交 `a73763a1a`：复用现有 Agent 工作台、workflowConfig、ResourceGrant 与文档绑定，实现用户、Agent、任务权限交集；经现有签名回调暴露文档、新闻、金融只读工具。新闻委托现有 News Runtime，金融目录与明细分别委托 FinancialAssetCatalogService、FinancialDataStore。沿用 Evidence、任务预算、审计和引用解析，逐次授权及重新读取来源，失效后隐藏旧结果。没有新增索引、采集器、数据库、RAG 服务或专用 Agent 镜像。

P1 提交 `083c19cc7`：按资源范围渐进加载新闻、金融和证据分析 Skills；补充引用时间、原始记录及来源链接，合并探索进度。微软技能的原始路径、版本和 Azure 依赖见[技能审查](runtime-resource-exploration-20261104-skills.md)，没有把 Azure SDK 当作 OpenSearch SDK。

P2 修复集成验证发现的问题：现有 SkillCatalog 配置归一化保留并校验资源策略；CodingRuntimeContext 接受受限资源范围；金融 DATA_ANALYSIS 任务保留受控工具；资源查询保留 OpenSearch 预算并跳过可选的 Java 模型改写；来源使用过的会话不再通过普通 SQL/文件任务历史上下文旁路披露。新闻行业筛选明确为文本条件，金融许可限制在明细查询前执行，来源 URL 排除凭据。

本地验证包括 259 项 Java、170 项 Node 全量测试、118 项资源交互前端测试和 62 项 Python/可视化回归，前端生产构建通过。详细计数与套件见 [P2 本地验证](runtime-resource-exploration-20261104-evidence/p2-local-verification.json)。SQL Studio 语法补全在并行构建负载下曾超时，独立串行复测结果另记，不扩大超时阈值掩盖问题。

发布复用既有分模块部署与回滚脚本：校验上传摘要，保留未改动 JAR 条目，使用现有镜像离线构建并运行 worker 测试；部署前拒绝活动任务、活动 Cline 会话和 Python 沙箱，保留原容器、配置与数据库备份。新闻与 MCP 保持原有独立服务拓扑。

实际联调进一步发现，认证过滤器返回 401 不代表 Spring 应用已经完成初始化。MCP 现提供仅返回状态的 `/readyz`，以 ApplicationAvailability 为准；部署按 MCP/API/worker/代理、新闻生产者的顺序启动，生产者启动前等待 MCP 完成初始化，避免单连接写入池在启动时被采集抢占。回滚旧镜像保留兼容判断。来源校验新增固定原因码与异常类型日志，不记录原文、查询或凭据。50 个混合业务问题见 [验收问题集](runtime-resource-exploration-20261104-evidence/mixed-questions-50.json)，问题集的存在不代表已经完成运行或语义验收。

能力限制：金融数据可能仅有每日热数据与每周归档，不能承诺完整日线；缺少单位、复权或交易所元数据时返回未知；行情快照不代表实时行情。当前资源探索为受控只读任务，未将其宣称为任意金融 Python 计算；已有绑定业务 MCP 工作流继续使用原有执行路径。复杂 PDF 表格、图文版式、页码补全与高级跨版本比较尚未在本轮实现，不能编造原始索引不存在的页码。95% 语义引用正确率与 10 秒 P95 必须通过真实验收衡量，不能由接口或单元测试推导。

进一步消除来源复核中的全绑定文档重读：DatabaseSkillExecutionScopeService 已逐次计算当前用户授权与 Agent 绑定的交集，CodingKnowledgeService 直接使用该限定 ID 集作为召回范围；实际命中、阅读与引用的文档仍经原文入口重新授权、验证租户及内容版本。金融/新闻上下文不再打开未使用的全部文档。没有跨请求权限缓存或原文缓存。

线程采样显示另一处成本来自同一批引用逐条重复加载完整资源授权图。来源复核改为每批 IO 前、后重新获取授权交集，再逐项校验来源身份、任务白名单与指纹；读取期间撤权仍会拦截整批输出。授权交集是方法局部值，后续请求、工具和模型轮次不复用。新增回归覆盖读取期间撤权、下次校验重新查询及金融任务不读取无关绑定文档。

进一步区分数据使用与内部记账：知识工具自身的前后校验覆盖该工具回调，私有 SDK 检查点及已停止模型调用的用量结算不重读来源；合同哈希、租约、围栏和执行状态仍校验。每次实际模型发送与历史响应重放仍校验最新来源。资源任务增加按需阅读相关原生 Skills、小页检索及发现证据缺口后停止的指导。慢来源校验仅记录任务 ID、引用数和耗时，不记录问题、原文或凭据。补充的 108 项 Java 回归通过，但真实 Agent 性能和成功率仍以端到端记录为准。

真实线程采样进一步定位到原有 FinancialDataStore 的 H2 行情全表扫描和窗口排序：证券代码按通用动态字符串保存为 CLOB，精确筛选仍耗时约 1.8～2 秒，多轮复核放大了开销。H2 启动与原有建表流程现在检查证券代码及既有索引；仅缺少以代码为首列的索引时，将 CLOB 保值转换为 H2 非限长 VARCHAR，再建立代码/日期索引。按首列识别已有索引，不依赖索引名称；MySQL 不执行此优化。业务字段、查询、权限、去重、时间范围和归档语义不变。迁移前后查询结果、长标识、已有自定义索引、周归档及首次只读副本尚未发布的场景均有回归覆盖。金融存储/读写隔离/资源接口 28 项测试通过；部署在停止写入服务后备份原金融 H2 文件，备份成功才启动新服务。

R10 实际部署未通过就绪检查，已自动回滚至 R9：约 763 MB 表的保值重写被原有 20 秒查询超时取消。金融文件备份成功且保留。随后将该离线维护与服务查询分离，DDL 单条语句限 180 秒，维护发布的 MCP 就绪等待限 600 秒；业务查询超时与 420 秒 Agent 验收时限不变，已有索引名称冲突时保留原定义并跳过优化。19 项存储复测通过，另有断言确认服务 JdbcTemplate 的查询超时没有被维护阶段提高。不能将 R10 当成已部署成功或端到端通过。
