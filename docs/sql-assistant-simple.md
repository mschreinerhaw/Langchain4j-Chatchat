# SQL Studio 简洁对话与 Agent 隔离

2026-10-21，分支 `feature/runtime-os-silo-workspace`。

SQL Studio 左侧不再展示用户空间文档区域。AI 工程助手移除代码解释、生成、修复、优化四个模式标签、输入框下方的 @/Mapping 图标，以及初始快捷建议和相关资源列表。保留对话、真实任务进度、候选代码审查和发送框。普通问题通过同一对话入口提出，工程请求可以生成候选文件；解释类问题应在答复中说明并返回空文件列表。

文档、参考 SQL 脚本、Mapping 文档及工程文件引用统一放入默认折叠的“工程上下文与执行设置”。“文档与参考脚本”子区域同样默认折叠，按需上传或选择用户原件，继续支持参考规则（RULES）和分析依据（EVIDENCE）。文档原件、所属用户校验、任务快照和上下文恢复使用原有链路。当前文件和选中的代码仍可作为工程上下文。

## Agent 列表与执行校验

SQL Studio 使用专用 `GET /api/v1/data-science/sql/agent-options`，不再调用管理端角色绑定列表。返回值仅含 `id,name,marketStatus`，候选必须同时满足：

- 当前状态为 `published`；管理员也只能看到已发布项。
- 当前认证用户通过现有角色 Agent 绑定或维护的全部 Agent 权限获得使用授权。
- 当前用户具有数据车间及工作空间访问权限。

没有可用授权项时，页面隐藏 Agent 执行切换和 Agent 选择框，只提供模型设置。Agent 模式必须显式选择可用的已发布 ID，不提供隐式默认 Agent 回退。前端再次过滤发布状态，后端仍作为授权依据。

生成准备阶段在文档、元数据读取和规划之前检查 Agent 的发布状态、精确 ID 和用户授权；Coding 提交及恢复阶段再次校验，撤权或下架后拒绝继续提交/恢复。模型模式不要求用户获得 Agent 授权。读取结果、审查及取消使用既有工程与任务归属策略。

## 验证

20 项后端测试通过，覆盖授权用户候选集、草稿/未知/无权 ID 拒绝、选定 Agent 的模型解析、撤权/下架后的提交与恢复拒绝、文档上下文和工具策略。66 项 SQL Studio 前端测试通过，最终设置折叠调整另通过 8 项组件测试，生产前端构建通过。

服务器用两个临时用户验证 11 项接口检查：有授权用户只返回指定已发布 Agent，无授权用户返回空集；给草稿绑定角色仍不可选，伪造 ID、撤权后准备及匿名请求均拒绝，不创建生成记录。浏览器检查左侧脚本区域、简洁对话框、设置内上传 SQL 参考与用途选择、工程脚本引用、有/无 Agent 权限的差异和无页面异常。未调用模型、未执行 SQL 或 Python，验证后清理临时用户、角色、工程及上传。
