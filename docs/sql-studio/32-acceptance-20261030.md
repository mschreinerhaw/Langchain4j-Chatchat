## 实际验证层次

1. 原问题回放：原任务实际 `workspace_metadata`、`workspace_validate`、`workspace_propose` 回执及快照；旧解析程序直接从生产 JAR 提取，以真实目标方言 Hive 运行。复现没有重新调用模型、增加预算或删除校验。
2. 数据库协议集成：H2 的真实 JDBC `DatabaseMetaData.getTables/getColumns/getImportedKeys` → 生产 `SqlMetadataDiscoveryWorkflow/Service` → 真实持久化项目/用户绑定 → 锁定 SQLGlot → 文件交付。配置和传输使用受控适配器，元数据来自实际 JDBC 表，不是手写 Mock 表字段。
3. SDK 修复集成：真实子 Node、Cline SDK、签名 HTTP、Java/A2、H2 日志及 SQLGlot。确定性模型先提交不存在字段，收到真实诊断后修订，再保存完整 SQL 和证据。
4. 真实模型集成：使用原失败任务实际选择的 `qwen3.7-plus` 及已有配置；真实 `ClineRuntimeModelBridge`、Cline SDK、上述 JDBC 结构和证据事务。最近一次 Hive 用例耗时 **39,340ms**，**6 次模型调用、7 次工具调用**，交付两个文件，`COMPLETED`，代码/SQL 执行次数0。它不是生产 Oracle 业务账号复验。
5. 前端：组件回归及实际浏览器，接口样本有明确标记；前端浏览器不冒充真实模型或生产数据库端到端验收。

## 仍需保留的风险

1. 静态字段存在性、已声明外键与业务统计口径是不同证据。分母、去重粒度、币种、有效委托/撤单筛选和源表到 Hive 的落地命名仍需业务审查，不能因解析通过认证业务正确。
2. 生产原任务使用已采集的版本化 Oracle 元数据。本轮没有在业务身份下重新刷新全部原始结构，恢复 SQL 仅对该任务原快照负责。
3. `GET_TABLE_DDL` 只生成授权可见列结构，明确不含未采集的完整数据库约束、存储属性或隐藏字段，不能用其重建完整源库。
4. 新操作需要 API、MCP 和 worker 使用同一版本，并通过既有注册目录刷新后验收。本轮尚未部署，不能仅更新前端就宣称生产问题已解决。
5. 要完成原始全量 P0 的执行/修复验收，还需独立、显式授权的目标数据库执行范围及相应数据库驱动/错误位置/空结果/恢复测试。当前 Hive 生成任务仍禁止向 Oracle 试执行。
