# Studio 上下文选择与逻辑文件夹

2026-10-21，分支 `feature/runtime-os-silo-workspace`。

SQL Studio 数据库浏览器保留表名、字段插入与元数据补全，并增加独立的表勾选列表。展开表只查看字段，不会自动成为生成依据。选表跨数据源、数据库、Schema 和分页保留；切换工程或身份后清空。一次最多选择 16 张表、8 个数据源，可以移除或清空。

“工程上下文与执行设置”中的文档入口改为紧凑文字按钮：上传文档、选择已有文档、选择知识库文档。知识库入口和手动勾选的参考脚本都放进“文档与参考脚本”。移除自动铺出的 `@文件` 按钮；参考脚本默认不选，后端也不再将整个工程的 SQL 内容自动加入生成上下文。用户主动选择的引用与代码片段才作为依据；工程文件版本仍用于生成结果的冲突检查。

Python Studio 助手移除顶部模式标签与底部操作下拉框，技能入口合并为“已发布技能”文字按钮。

两个 Studio 都支持逻辑文件夹改名和删除，SQL Studio 还可以修改完整路径以移动整个子树。删除使用统一 `AppConfirmDialog`，保留脚本和子文件夹并移到上级；同名冲突时拒绝整个操作。SQL 文件身份、内容和版本历史保留，路径变化增加版本；未保存编辑、旧版本和工程越权都不能覆盖现有内容。事务内先释放移动文件的旧路径键，处理 `a/a/query.sql → a/query.sql` 等重叠路径。Python 文件夹禁止移动到自身或后代。

## Runtime 与 Cline

生成接口沿用 `codingMetadataSelection`，兼容原来的单组格式，并支持跨范围分组：

```json
{
  "codingMetadataSelection": {
    "sources": [
      {
        "discoveryId": "服务端保存的上下文 ID",
        "bindingId": "服务端绑定 ID",
        "expectedSnapshotId": "元数据快照 ID",
        "tables": [{"tableName": "orders", "database": "sales", "schema": "public"}]
      }
    ]
  }
}
```

客户端只提交所选表身份。Runtime 通过已注册 MCP 元数据服务重新校验所属用户、绑定、访问权限、完整库表身份和快照，再读取字段类型、注释和键标记。不同服务、数据源或命名空间中的同名表保持独立。凭据与任意返回字段不会加入生成上下文。生成、提交和恢复时都重新验证权限与快照。

授权表结构进入既有 `CODING_WORKSPACE_INPUT` 事实快照；Cline 通过 `workspace_read` 读取相同的 `schema` 和工程上下文，再提交脚本建议。没有新增数据库执行通道。跨库选表用于分析与生成，实际跨库执行仍取决于用户数据库引擎和连接能力。
