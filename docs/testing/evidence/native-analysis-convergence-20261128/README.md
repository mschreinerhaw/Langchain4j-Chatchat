## 针对性改动

经 Java 签发并冻结为报告和结构化结果的普通数据分析任务，由 Worker 按报告模式扫描两个交付目录。文件名由任务选择，报告和结构化结果各一份。其余输出留在工作区。HTML 的同目录资源仍可交付，专业报告校验仍受原配置控制。Worker 仍要求真实的原生完成事件，生成哈希后交给 Java 作原有业务结构校验，再进入原封存、上传、完整性校验与状态流程。Studio、已有绑定及其他原生产物任务继续使用原显式选择方式。

本地回归通过 55 项 Java 测试（1 项跳过）、147 项 Cline Server 测试（13 项跳过）、30 项 Gateway 单元测试和 1 项 Gateway HTTP 回归。Linux 候选镜像内通过 159 项 Cline Server 测试（1 项跳过）。服务器已从源码构建独立 API 与 Worker 镜像，使用既有 Gateway 和独立的 API/MCP 数据库、Temporal 队列、Silo 桶及 Worker 目录。构建源码补丁 SHA-256 为 `b2994de1063dc5ff3785836afae76e169c0f22b626f0f316b206001d39cda714`。

第一次隔离复跑两项均在 Worker 分配阶段终止。Executor 原始回执记录 `ENOENT`，原因是隔离配置沿用旧目录下的工作区模板路径。已将模板和引用移至本次隔离工作目录；保留该批次失败记录，并重新走正式入口。

## 普通 Native 分析任务预算回归

部署私有配置的 `analysisBudget` 可按任务冻结 `minutes`、`modelCalls`、`modelTokens`。缺省保留现有策略，测试数值只写入隔离配置。模型调用数和 Token 预留使用现有事务化台账，按租户、用户、Run 和 Runtime Task ID 累计。Worker 与 Session 变化不会创建新额度。已知实际用量替换预留，未知用量继续占用额度，已确认未上游分发的请求可释放预留。过期或退役会话凭据仅可用于结算其原有回执。

- 普通任务 `69b5b4d9-c3d3-36cf-af62-0f6bd8d542a9` 在隔离配置的一次额度下，首个真实请求取得 6,937 Token 回执，第二次请求的 `providerDispatched=false`。Runtime 最终为 `BUDGET_EXCEEDED`，Worker 停止。
- 任务 `db2cc3b3-0330-3fc2-adef-24bd2c0e0e69` 的第一个 Worker 在取得 7,005 Token 后被强制退出，退出码 137。新 Worker、新 Session 使用原 Runtime Task ID，第一次请求即被额度控制拒绝，且无上游发送。Runtime 最终为 `BUDGET_EXCEEDED`，接管 Worker 正常停止。两项故障测试均未生成正式交付，也未计为业务报告成功。
