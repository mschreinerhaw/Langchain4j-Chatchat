## 复现与整改

| 问题 | 基线取证 | 修复与回归 |
| --- | --- | --- |
| 大 JSONL 轮询 | 原 Journal 构造时读取全文，分页先从全量内存数组筛选。Broker 的核心观测入口每次轮询都重新构造 Journal | Journal 根据游标按字节偏移定位，只解析所需页和查找点。Broker 核心、模型回执与诊断监控的事件列表走增量分页。追加继续使用持久化屏障，可在原始事件及其派生事件共同追加时合并 fsync |
| 停止 Worker 之后封存中断 | Linux HTTP/Unix 故障夹具中，归档失败导致旧版本重启之后仍联系已停止的 Worker，重试返回 503 | 保存封存意图、原生 seal 确认、manifest、停止回执、校验及归档检查点。Runtime 恢复交付时沿用原任务和原会话绑定。分阶段注入覆盖六个检查点，实际 Governance 进程强制退出用例通过 |

| 任务级预算查询 | 基线索引覆盖用户及角色，从租户、运行、任务、用户聚合额度时缺少对应索引 | 隔离 PostgreSQL 100,000 行夹具从顺序扫描变为索引扫描，查询执行时间从 32.847 ms 到 0.419 ms。独立锁夹具中，同租户仍串行，延迟约 1,924 ms，另一个租户约 167 ms。锁粒度保持现状 |

## 500 MiB 容量档与其余分档

Linux 验证服务器的样本由程序生成，每档仅创建一个受控大小的测试文件，临时数据位于 `/mnt/disk01`。每档模拟旧 Broker 对同一尾部游标重新打开 Journal 12 次，比较候选按游标分页。实际耗时受服务器并发和文件缓存影响。

| 样本 | 12 次轮询基线 → 候选 | 同批峰值 RSS 增量基线 → 候选 |
| --- | ---: | ---: |
| 10 MiB | 423.3 → 15.8 ms | 46.3 → 4.1 MiB |
| 50 MiB | 2,097.0 → 13.6 ms | 205.9 → 2.9 MiB |
| 100 MiB | 4,350.5 → 15.5 ms | 292.2 → 6.4 MiB |
| 500 MiB | 32,967.1 → 18.5 ms | 1,086.6 → 5.8 MiB |

500 MiB 档的同步事件循环延迟观测峰值由约 7,307 ms 变为约 2.46 ms，GC 后保留堆由约 501 MiB 变为约 0.12 MiB。单条 fsync 有明显波动，本试验支持减少成对事件的 fsync 次数，也支持分页改进，不能据此认定固定比例的写入提速。上述结果属于平台基准，与模型调用次数和计费无关。

在独立容器的 1 MiB tmpfs 内触发了真实 `ENOSPC`。原始四条事件留存，Worker 停止只执行一次，释放夹具占用后原交付进入 `SEALED_PENDING_UPLOAD`。 [受限空间测试](enospc.json)

## 验收范围

- Linux Node 回归 174 项通过、1 项需独立 Cline Core 源码产物的测试跳过。Gateway 31 项通过。Java 定向 70 项通过、1 项跳过，另在隔离 PostgreSQL 实跑 7 项账本测试。
- 扩展后的 Linux 夹具在基线上复现四项失败，分别为停止后封存、Native 已 seal 但尚未返回 manifest、结算端返回 503 后 Governance 被强制终止、预留接口接收请求后断开。修正版通过同样的四项回归。临时对象存储写入失败夹具中，从已封存状态重试后正常上传并通过验收回执重放。
- 封存检查点恢复与已有原生 Session 检查点续跑是不同能力。已验收的是交付恢复。Worker 在最终 manifest 持久化前彻底消失、真实 Java API 与 Silo 在途故障矩阵、原 Cline 会话断点续跑及生产类负载中锁争用 p95 仍需要专项验证。
- 独立工具、代码、任务级异常重试预算和更低但经过验证的输入 Token 上界仍待完成。现有监控的分页事件列表已经增量读取，诊断详情的历史聚合和大归档从 Silo 读取仍需要单独验证。
