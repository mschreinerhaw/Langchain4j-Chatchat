业务源码参考版本为 `d3b35d1b1`，此前运行证据为 `582e0722e`。本轮候选源码为 `cd6935487`。隔离验证使用原有对照环境和授权资源。Agent API 文档的工作区改动独立保留。

## 阶段报告与正式结果

Runtime 在固定授权输入后读取已验证的快照和统计证据，使用原报告 Schema 和交付规则校验阶段报告。报告保存在按租户、用户、运行和任务隔离的执行检查点。授权调用方可在 Native delivery 回执中通过 `preliminaryReport` 查看阶段报告及其版本、输入快照版本和摘要。读取要求任务状态允许，且身份和 Agent 权限仍有效。待核对的停止、用户取消及披露限制阻止预览。

阶段报告没有 Native 完成回执和正式文件下载标识。若智能分析在安全收敛后转为可信基础报告，正式 Silo 产物仍经过原有回读和校验，回执记录 `basedOnPreliminaryVersion`。若智能报告通过正式交付，Runtime 标明最终结果替代的阶段版本。

## Docker 结构协议取证

上轮智能报告首次预览时，结构化输出根对象缺少以下五个字段，形成三次修复模型回执，共计已知 97,310 Token。 [原始结构错误摘要](../native-p0-reliability-20261128/verification.json)

| 字段 | 可验证的数据来源与职责 |
| --- | --- |
| `reportMarkdown` | 报告文件内容可以由程序读取并校验。业务叙述由模型或已发布确定性规则生成 |
| `evidenceReferences` | Runtime 可以核验授权快照和实际显式引用。供给过的快照只表示可用，不能直接证明智能分析使用了它 |
| `limitations` | Runtime 记录供数和覆盖缺口。分析推断的局限需由分析结果提供 |
| `analysisStatus` | 供数、执行、验证状态可直接读取。完整业务目标的完成程度需要额外的已验证业务依据 |
| `fieldProvenance` | 由授权字段和计算规则的实际绑定支持。Runtime 可以校验引用，未知字段含义不能推测 |

本轮保留增强报告的 Schema 校验，调整结构修复的重复判定，使与失败 JSON 无关的报告修改不会重置重复计数。增强报告的受信字段自动组装仍需实现和联机验证。

## 上轮停滞取证

按工具调用 ID 关联开始和结束事件，再按工具名、参数摘要及输出摘要统计。InnoDB 的 26 个可关联调用有 25 种不同签名，Docker 的 27 个可关联调用有 26 种不同签名。两个任务各发现一组重复编辑失败，均没有足够证据证明整个分析过程持续卡在同一操作。InnoDB 最慢的成功或失败模型回执耗时 134.755 秒，Docker 为 142.737 秒。相同错误返工与慢推理需要分别判断。

本轮收敛改动限于已确证的交付修复无变化。一般工具循环、脚本重复执行及跨阶段进展识别仍待验证。本轮缩短的任务预算用于隔离故障对照，不能用来推导正常任务耗时分布。
