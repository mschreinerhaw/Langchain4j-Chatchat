第二条请求额外两项来源均有 `deliveryStatus=EMPTY_RESULT`、`sourceVerifiedEmpty=true`，没有将其作为成功获取的交割明细，也没有将其混同查询失败或未授权。实际业务日期和相应限制须由最终报告再次核对。

账户日盈亏与持仓日盈亏合计存在差额；相同字段缩写不证明相同统计范围。源字段 `LJYK` 声明为累计实现盈亏，不是浮动盈亏。`CJSL*CJJG` 仅为数量乘成交价，不含费用，不能直接当作交割现金流水。单日委托样本不能支持长期偏好结论。

输入完整性 PASSED 不等于最终业务 PASSED。脚本明确输出 `INCONCLUSIVE_UNTIL_ARCHIVED_REPORT_COMPARISON`，报告逐项核对前不得升级。

第三条请求模型自主选择了交割明细，实际为资产 1、持仓 20、交割 27，合计 48 条，与前两条的 37 条委托不是同一业务口径。独立脚本分别支持从真实交割 CJJE 或委托 CJSL*CJJG 重算，不替换交易数据，不强行要求每次都是 58 条。

第四条请求仅选择两个 SQL 模板，均无业务行。独立脚本核验实际零行文件后返回 `INCONCLUSIVE_VERIFIED_EMPTY_SOURCE`，客户/日期不能逐行核验，且不计算虚构的零资产。这不证明其他授权 API 没有该客户数据。第五条请求明确从已授权客户 API 取数，由模型自主选择模板及参数，恢复取得 58 条记录；未指定模板 ID 或扩大权限。
