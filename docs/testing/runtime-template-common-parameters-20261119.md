# Runtime OS 模板公共参数复用验证

## 合同与执行

- 选择器保留每个候选的发布身份、业务说明和资产信息。调用模型时，按规范化后的抽取 Schema 分组。同一组只发送一份参数 Schema，模型用 `templateIds` 明确指出该组参数适用的模板。历史单模板提案继续可读。
- JSON 对象的键顺序不参与分组。参数名、类型、说明、默认值及其他 Schema 约束保留在分组判断中。每个模板根级必填规则仍独立执行，允许抽取合同相同而必填集合不同的模板共用一份提案。名称和约束不同的字段需要发布合同明确对应关系；当前没有引入名称猜测。
- 不同资产可以共用 Schema 表达。Runtime 拒绝跨发布资产共用值，检查组成员，限制展开总数并为每个模板分配独立绑定 ID。开放发现保留模型的多模板语义选择，固定发布保留发布者确定的范围。
- Runtime 扩展模型提案时保留同一份来源证据，再使用每个模板的原始参数合同和执行权限检查。通过的参数直接进入原执行链路。框架共用这一过程，模板类型不影响参数复用规则。
- 模型已尝试但未通过校验的可修复必填字段，最多触发一轮字段补丁。补丁请求只含原始问题、发生错误的字段及其 Schema，不含完整模板目录。Runtime 固定模板和有效字段，拒绝越界补丁。未提供的值、已采用的有效默认值、无可定位字段的对象约束和无效引用保持原有失败或缺输入状态。结构化选择协议出错仍走既有有界纠错。
- API 的网络、权限和服务失败位于参数绑定之后，调用原失败隔离执行器。此改造没有增加任何 API 重放。原有跨进程恢复及未知操作对账继续由 Runtime 自身负责。

## 对照配置

基线使用此次改动前已编译的同一工作区版本。对照夹具固定一个合成账户问题、五个候选、三个正确业务模板和同一组参数，其中包含一个需要原文证据的日期。复用前后三个业务模板均需分别执行。夹具导出两个 Java 版本实际组装的函数请求。真实模型探测使用同一台服务器的 `qwen3.7-plus`、`AUTO`、300 秒超时、非流式、无请求重试，按前后、后前顺序调用。模型探测只验证模板选择和参数，未执行 API 或读取客户数据。

| 度量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 抽取 Schema 变体 | 3 | 1 |
| Function Schema 字符 | 2,484 | 1,278 |
| 单次输入 Token（供应商回执） | 1,230 | 903 |
| 每次返回的公共参数结构 | 3 | 1 |
| 第一组输出 Token / 耗时 | 718 / 12.642 秒 | 435 / 8.042 秒 |
| 第二组输出 Token / 耗时 | 708 / 12.184 秒 | 634 / 11.260 秒 |
| 两组模板与参数黄金断言 | 2/2 | 2/2 |
| 每次模型调用 | 1 | 1 |
| 本地故障注入中 API 子调用次数 | 3 | 3 |
| 本地故障注入中保留成功结果 | 2 | 2 |

Schema 缩小约 48.6%，真实输入 Token 减少约 26.6%。有一个子调用模拟网络故障，两版都各尝试三个子调用一次，并保留另外两个成功结果。失败没有重新进入绑定模型。以上是选择及执行层小样本，生产业务成功率与跨进程恢复没有用真实业务数据做对照。
第三组增加了对原文日期证据的检查，两版均返回正确的模板、参数和原文引用。输出 Token 为 594 → 672，耗时为 10.538 → 11.954 秒。该组优化版更慢，三个真实样本只能说明此次夹具中输入和重复数据的变化，无法推断生产尾延迟。

## 验证

- Java 92 定向回归覆盖共同参数来源、资产隔离、不同参数合同、独立必填校验、定向修复、非法返回、执行权限和单子调用失败隔离。
- 在合成风险用例设置 `-DtemplateRisk.probePath=<file>` 会导出请求到相应文件。对照夹具通过 `-DtemplateCommon.baseline=true` 使用旧单模板响应和基线断言。真实模型回执及定向回归日志位于工作区外层的 `target/template-common-*`，回执只保留计数和断言结果。
