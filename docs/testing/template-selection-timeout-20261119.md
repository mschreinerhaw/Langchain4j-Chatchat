# 有限算力环境模板选择超时专项整改

## 生产排查

只读检查了运行版本 `source-20261119-cline-context` 的 Java Agent 日志。两次模板绑定入本地执行器的等待分别为 1 ms 和 0 ms。成功请求的输入估算为 2,496 Token，模型调用用时 106.004 秒。失败请求的输入估算为 2,492 Token，在 300.009 秒返回 `dev.langchain4j.exception.TimeoutException`。同一时间段 Agents 选用 `qwen3.7-plus`。可确认失败点在模型请求阶段，日志没有首 Token 数据，无法从中确定服务端排队、首 Token 或生成耗时。生产历史的估算值与下面供应商探测的实际用量采用不同口径。

## 源码改动

- `SchemaDrivenTemplateParameterBinder` 合并返回格式、证据、缺值和默认值指令。开放选择继续保留候选的用途、身份、参数契约和业务范围，且要求选择完成请求所需的全部互补模板。标题与描述完全相等时只发送一次。函数 schema 还保留参数类型、枚举、日期格式、描述、默认值及证据字段。
- 当前任务没有可用的完整记录集时，从请求移除无法使用的 `parameterBindings` 结构和相关指令。有授权记录集时仍给出字段、路径、行数和原有小预览，执行解析用完整记录集。模型提案沿用原有身份、权限、参数类型、必填、证据和默认值校验。
- 保留 `ToolChoice.AUTO` 和一个指定函数，通过响应协议验证结果。已有选择复用及确定性工具结果准入继续用于原场景。超时不会触发协议纠错。纠错仍只处理可修正的响应问题，原校验保留。
- Java 模型执行接入任务取消检查，继续受任务截止时间和预算约束。模型诊断区分全程未见活动 `MODEL_NO_RESPONSE`、独立首 Token 上限 `MODEL_FIRST_TOKEN_TIMEOUT`、流式进入生成后完整响应超时 `MODEL_RESPONSE_TIMEOUT`，以及无法细分的请求超时 `MODEL_REQUEST_TIMEOUT`。任务总预算耗尽由原截止机制终止。数据供给失败保留原因，未知行数在 `dataObservation` 中仍为 `null`。
- Coding 每轮预算指令略缩短，移除已通过门禁检查的空 pendingOperations 列表，明确按引用读取归档证据。恢复对账、未结算用量、强制结果校验、最新执行诊断和授权读取保持原有检查。既有按需代码、技能及数据引用路径继续使用。

## 同模型实测

使用 Java 各版本实际组装的合成账户风险请求，基线为 `1540f612c`。开放选择给出五项相同候选，黄金答案要求选中持仓、交易、资金，保留带前导零的账号和日期。固定发布模式只给定这三个由发布者确定的模板。请求通过同一台生产主机、现有 `qwen3.7-plus` 配置，逐个顺序发送到模型。每次使用相同 300 秒请求超时、无自动重试、相同 ToolChoice 和输出配置。流式单列，顺序在组间反转。探测只调用模型，未执行 MCP、未读取客户数据。

额外测试把同一份精简固定发布请求的 ToolChoice 改为 REQUIRED。该次 qwen3.7-plus 调用接受配置，并返回正确的三个绑定，用时 10.138 秒，输入和输出分别 1,031 / 587 Token。单次验证只建立这个端点的兼容性，源码默认仍为 AUTO。

开放选择的输入 Token 降约 34%。流式首活动（包括文本、推理或工具调用增量）为 1.001 → 0.992 秒，单对样本差异很小。非流式无可观测首 Token。固定发布的第 1 组输入降 32%，但成功请求输出更长，耗时明显增加。基线的较短耗时对应无有效函数的业务失败。各请求的模型调用次数均为 1，本次没有重放任务。样本量不足以推断生产超时率或负载下的尾延迟。

### 轻量模型探测

现有 deepseek-v4-flash 使用同样的精简请求和 AUTO。开放选择一次耗时 2.043 秒，输入 / 输出为 1,552 / 390 Token。两次固定绑定耗时 2.492 / 2.194 秒，输入均为 1,049 Token，输出分别是 396 / 407 Token。三次均在一个函数调用内通过三个模板和参数的黄金断言。这是独立的候选模型探测，性能验收仍以同一 qwen3.7-plus 的前后对照为准。

## 回归和剩余风险

- Java 定向回归 73 项通过。基线 worktree 的开放选择和固定发布对照夹具均通过。测试覆盖多模板选择、授权记录引用、数据缺失、响应截断、首 Token、完整响应、取消与预算。兼容 Coding SDK 定向回归 60 项通过。Cline Server 123 项通过，7 项按环境条件跳过。
- 生产日志和直连探测覆盖了调用诊断、选择和参数准确性。实际业务成功率、持仓计算结果及端到端延迟仍需要将两版部署到隔离环境，用同一可授权数据快照、相同 Worker 和并发压力验证。当前生产实例继续提供现有版本服务。
- 生产模型配置里有较轻量的可选模型，但当前任务链路冻结的是单一授权模型。没有任务内次模型授权、函数能力和预算契约，当前未接入自动回退。未来回退需在数据读取前录入该任务的双模型授权，登记同一工具协议，复用总预算，并只在明确的模型失败且无未知工具操作时尝试一次。
- 收敛输入后仍然可能遇到高输出推理、拥塞或 provider 请求超时。固定模板成功样本与开放选择使用不同函数协议，需分别统计实际尾延迟及交付。生产首 Token 指标需要对已经确认兼容的编解码配置采样。
- Java 测试 `SchemaDrivenTemplateParameterBinderTest` 的风险夹具支持用 `-DtemplateRisk.probePath=<file>` 导出合成请求。在基线 worktree 复制同一测试文件并加 `-DtemplateRisk.baseline=true` 可重建输入。运行日志和只含计数的供应商收据保存在工作区外层的 `target/template-risk-*`。
