# Tool reviewer 提示词与阶段性能优化

2026-10-25 已通过 Live Monitor 发布生产并完成真实任务验证，见 [生产验证记录](tool-review-production-validation-20261025.md)。本文及原 evidence 目录保留发布前的离线测试快照。

`chatchat-chat` 的 `RUNTIME_OBSERVATION` 是事件桥接结果，实际审查在 `chatchat-agents/AgentOrchestrationEngine.reviewInterpretationPlanToolResult`。一次“模型审查工具结果”可能包含候选语义审查、独立覆盖审计、受控 schema 参数绑定三阶段；不能把整个观察项的持续时间都解释为第一轮模型推理。

## 实际修改

- 新增 `ToolReviewPromptContext`：在单次请求内对相同 schema、参数契约和声明语义建立共享值字典；候选通过 `$runtimeReviewRef` 引用。编码阶段可恢复为原 JSON，不跨运行缓存数据或复用模型结论；保留字碰撞用 literal 编码隔离。没有重复内容的小输入不会因字典格式而变大。
- 当前候选仅构建一次语义投影，不先格式化完整原始结果再丢弃。移除重复身份目录和整个列表的前缀截断，尾部候选仍保留自己的声明能力。沿用现有单字段投影策略；完整原始对象仍由 Runtime 保存和验证。
- 历史上下文优先直接依赖和最近步骤。已经审查过的历史候选只提供身份、目标与分页引用，不重复发送整套候选 schema；声明遗漏步骤数量。当前步骤输入不再在累计上下文重复出现。
- 为 reviewer 增加 `chatchat.agent-runtime.tool-review-step-input-max-chars`，默认 4000，非正数保留旧的完整输入行为。超预算参数值用步骤、参数名、字符数和 SHA256 引用，小参数仍可见。此预算针对保留的参数值，引用元数据另有少量开销；不改变原计划、执行输入、参数绑定或数据分析输入。引用不代表证据不存在，也不允许模型编造/重绑未看到的值。
- 通用事实约束改为工具准入阶段版本，不反复注入最终报告排版、分块分析和原始重放的完整说明。独立覆盖审计、跨资产授权、原生 Function Calling 和 Runtime 参数验证仍在。
- 增加准备、第一轮模型、覆盖检查、参数绑定和总耗时，以及提示词字符数和估算 token。覆盖审计也记录实际模型输入与响应耗时。完整模型 JSON 改为 DEBUG，INFO 只记录指标，避免同步格式化/写入长结果。
- 增加 `TOOL_REVIEW_STAGE` 观察项，前端分别显示“模板覆盖检查”“受控参数绑定”，按步骤及尝试合并开始/结束状态。它们是工作流阶段，不将空 schema 的确定性绑定冒充一次模型调用。
- 补齐模型空响应的空值元数据处理；第一轮模型结束后再次检查取消，避免已取消任务继续调用覆盖审计或绑定模型。

## 定量结果

相同的 30 候选合成夹具，使用同一 `ContextTokenEstimator` 比较：

| 指标 | 优化前 | 最终版本 |
|---|---:|---:|
| 第一轮提示词字符数 | 30,445 | 17,706 |
| 估算输入 token | 8,271 | 5,047 |

字符数减少约 **41.8%**，估算输入 token 减少约 **39.0%**。该夹具包含重复声明/schema，并检查全部候选 ID 和尾部独立能力仍然存在，不含真实客户数据。另一个用例将 220,000 字符的已解析参数保留在原执行计划中，仅向 reviewer 提供引用，整份审查提示词小于 20,000 字符。

这不是线上响应时间或真实计费 token 的对比。离线验证阶段采集的生产日志尾部没有匹配的审查指标，当时尚未发布；后续已完成生产发布，并从历史任务事件取得参考耗时，详见生产验证记录。完全不同的候选语义不能依靠无损去重缩小，仍需遵守上游候选分页和请求上下文预算。

## 验证与边界

- Java 定向回归 **38 项通过**：字典编码/恢复、保留字碰撞、请求隔离、全部候选能力保留、依赖与最近历史、原输入不变、大输入引用、取消、空响应、覆盖审计保留、空 schema 单模型调用、原生绑定约束，以及 `chatchat-chat` 的事件桥接。
- 前端 **73 项通过**：观察项、聊天视图、消息列表；Vite 生产构建成功。生成资源不作为本次源码变更提交。
- `chatchat-chat` 及依赖的 package 构建与上述定向测试通过。
- 修改前已存在的 `AgentOrchestratorTest`：138 项中 39 失败、35 报错。修改后该旧类仍未全绿；逐测试名比较不增加失败用例。不能据此宣称全仓测试通过，详见证据 JSON。
- 仍保持所有未选候选的独立覆盖检查，不通过跳过语义审核、只选前几个候选、按业务名称硬编码或更换模型来制造性能收益。已有确定性准入路径和空 schema 绑定策略不变。

基准与回归结果在 [tool-review-performance-evidence](tool-review-performance-evidence/)。正式发布后应比较同类任务的准备时间、三阶段耗时、输入/输出大小、失败率与选择覆盖质量，再确认真实端到端收益。
