# 部署、迁移与回滚

产品发布标识为 `2.0.0-rc1`，独立于已有 Maven 内部模块坐标。发布目录的 manifest 记录源代码 commit、两个 JAR 的 SHA-256、部署镜像与基线标签。不得以旧日志或历史包代替本次构建结果。

## 迁移顺序

1. 完成定向后端、既有授权集成、前端回归及两个前端构建。
2. 打包 API 和 MCP，核对 SHA-256；上传构建包、迁移 SQL、镜像模板和部署脚本，凭据不进入发布包。
3. 在目标服务器运行 `scripts/deploy-unified-management.py --release-dir <release>`。该脚本先构建干净运行时镜像，检查活动分析任务，再备份数据库、当前 JAR、Compose 和导航配置。
4. MCP 数据库执行 `V20261022_03__mcp_tool_releases.sql`；API 数据库执行 `V20261022_02__unified_management_control_plane.sql`。后者新增功能权限与工作空间，仅为已有且具有角色授权能力的 SUPER_ADMIN 赋予新管理功能，不新增工具或数据授权。
5. 替换 API/MCP 容器，保留 Node/Cline、Sandbox、SILO、OpenSearch 和服务端资源限制。API 启动时迁移标准管理导航；MCP 把既有模板绑定复制为版本快照，保持 enabled、角色和固定模板范围，不改原绑定。
6. 对原工具授权、资源授权、用户角色关系和固定模板绑定执行迁移前后指纹核对。原 `mcp_authorization_role` 表只作为回滚档案保留，新执行授权不读写它。
7. 执行真实控制面验收、浏览器验收和 Runtime 分析回归。验收临时发布版本最终下线，保留历史以供审计；临时用户、角色和租户由 `verify-unified-management.py --cleanup` 清理。

## 配置分级

| 级别 | 内容 |
|---|---|
| 用户 | 名称、用途、模型、允许使用的已发布工具、必选工具与受控工作流 |
| 管理员 | 模型供应商、连接凭据、工具发布、数据源、运行策略和预算 |
| 服务端内部 | 资源限制、执行超时、重试、沙箱、插件、存储、临时目录、日志和服务认证 |

普通用户提交查询服务配置时，服务端保留旧服务的运行策略和内部设置；新服务采用默认策略。隐藏页面控件不构成授权。已有模型路由、能力识别与确定性模板执行保持原职责，不向模型授予新资源。

## 回滚

2026-10-22 的 RC1 远程启动发现 JSON Schema 依赖覆盖问题：MCP SDK 2.0.1 要求 networknt 2.0.4，而新增校验器曾指定 1.5.6。部署已自动恢复原镜像和导航；业务授权指纹保持不变。RC2 将 API 与 MCP 的运行依赖统一为 2.0.4，并新增真实 SDK 构建测试。重试时只恢复本次回滚停用的、新建且未定制的两个工作空间，不覆盖既有工作空间。

离线构建可以设置 `CHATCHAT_API_RUNTIME_IMAGE`，复用经过检查的纯 Java/Python/sqlglot 运行层；构建助手拒绝包含 app.jar 历史的基础镜像，验证 sqlglot 版本，并继续检查最终业务 JAR 层数和镜像大小。这样无需在部署停机期间下载 Python 包。

RC2 的远程验收进一步发现 DBA 创建新版本表后未交接应用角色所有权，以及新发布接口未登记到既有许可证目录。新表迁移现继承 `mcp_template_query_binding` 的表所有者；新接口复用原发布模块许可证，并继续接受内部服务身份和中央权限双重限制。RC3 同时要求 HTTP 就绪状态持续 20 秒，避免将 Spring ApplicationRunner 完成前的短暂监听误判为启动成功。

部署脚本启动失败或原权限/模板范围核对失败时，恢复原镜像与 Compose，并恢复旧导航、停用新空间。新增版本表与审计历史保留，避免丢失诊断证据；原 MCP 角色档案不删除。

完全数据库回退只应在停止写入并核对备份时间后执行。备份为 PostgreSQL custom-format 文件，可先用 `pg_restore --list` 核对，并恢复到新建验证数据库做比对。不要直接对正在使用的业务库执行覆盖恢复。确认需要整库回退时，将停写期间的新业务数据单独保留，再按备份与新旧库切换方案恢复。

已发布工具版本本身的回滚通过用户端“回滚到此版本”完成：恢复原不可变定义、重新检查当前授权、停用当前版本并刷新工具目录。它不能恢复已经撤销的数据权限。

## 兼容影响与清理

- MCP `/api/v1/mcp-authorization/**` 返回 410，独立权限维护逻辑已移除。
- MCP 旧模板绑定的写接口已移除，并由过滤器返回 410；只保留内部目录读取。
- 用户端统一控制面使用 `/api/v1/permission-center` 和 `/api/v1/tool-publications`。
- 旧中央工具授权接口保留，但租户来自登录上下文，不能跨租户移动授权或批量删除其他租户记录。
- 显式的用户或角色工具拒绝规则优先于超级管理员的默认工具访问权；没有显式拒绝时保留原管理员默认行为。此前实现曾提前放行管理员，RC5 修正了此顺序，并验证新增拒绝和移除拒绝均在下一次调用生效。
- 已删除 MCP 的 Settings、TemplateQueryPublications 页面、脚本、样式及其前端 API 封装。
- Agent Router 和 MCP 共用 `common.security.McpScopeExpression`，删除重复解析实现。
- API/SQL/Python/SSH/HTTP TemplateWorkflowPlugin 继续保留，它们服务现有确定性执行链路；本次不恢复自由探索数据获取。
- 不删除历史业务字段和权限数据。旧配置在保存时按分级治理，已有服务预算与必选模板绑定保留。
