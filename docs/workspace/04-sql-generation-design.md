# T09：SQL Generation 扩展预研

日期：2026-10-13。交付范围为设计，不包含 SQL 生成、SQL Studio 或数据库执行功能的开发。

## 1. 归属与入口

SQL Generation 是数据科学 Workspace 的业务 Skill。预留 Workspace 页面标识 `sqlStudio`、路由 `#/w/data-science/sql/studio`、功能权限 `capability:sql-generation`、Skill 标识 `sql-generation`。这些标识目前不在已启用的页面白名单或权限种子中，不能据此宣称 SQL Studio 已上线。后续在同一前端工程注册页面、配置菜单及 RBAC，再将页面加入 Manifest；Runtime Core 无需新增 SQL 工作流。

## 2. 输入与授权

输入包括任务说明、SQL 方言及版本、源目标表、Mapping 文档与 SQL 案例的资源 ID。文件引用、检索和工具发现沿用当前资源授权与资产发现链路；Workspace Manifest 只声明需求，不发放文件、数据源或 MCP 权限。不能将前端传入的 Workspace ID、文件路径或数据库名称作为授权依据。

复用现有文件、文档检索、Skill 目录、MCP 工具以及任务和产物服务。先以只读、脱敏样例验证映射；无权限资源由既有服务拒绝，模型可以使用其他已授权证据或说明缺口。

## 3. Skill 的分析方法

Skill 指导模型辨认映射版本、来源、字段关系、主键、转换规则、空值、重复值、增量条件及目标方言。案例只能作为参考，不能覆盖当前 Mapping。存在冲突或关键字段缺失时，输出待确认项，不编造表名、字段及业务规则。

模型在授权范围内自主决定检索、探索、计划和校验次序。方法说明不规定固定 Agent DAG，不新增执行状态机，也不将业务步骤写入系统通用提示词。最终交付前由模型核对字段覆盖、连接条件、聚合粒度、方言语法和正文与限制说明的一致性。

## 4. 校验与产物

通过既有工具目录发现与目标方言匹配的 SQL 校验工具，使用服务端真实工具输入契约。校验优先使用解析或隔离环境中的 EXPLAIN；生成任务不默认授权执行 DDL/DML。需要写库时单独使用现有授权、确认机制。

结果应包含 SQL 文件、输入证据清单、逐项映射说明、校验结果和未解决问题。下载复用现有产物服务，继承任务的租户、用户及 Workspace 来源；后台生成不能读取浏览器当前空间。文件名不应允许路径穿越。

## 5. 离线评测与实施次序

使用固定、授权的 Mapping 与案例测试集，对比 Skill 版本和模型；评测覆盖字段准确率、方言解析、连接与聚合语义、缺证据时的结论、跨租户拒绝和可下载产物。评测判断报告质量，不向 Runtime 加入替模型判业务结论的规则。

先完成真实数据库上的 Workspace 迁移与后台任务验收，再注册 SQL 页面和权限，建立只读校验工具，最后开发 Skill 与产物展示。验收通过后才讨论 SQL 执行能力。此方案没有新增模型调用、工具调度、Agent Loop 或规划器。
