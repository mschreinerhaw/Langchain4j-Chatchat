# Frontend Resource Hub P0

Two services: an immutable file-backed resource API and an isolated Playwright worker. No management database or P1 resource editor is introduced. Native Cline owns generation and repair; Runtime owns permissions, budgets, task state and Silo archival.

## Build and deploy

Use `npm ci --ignore-scripts` and `npm run build` for local assets. `package-lock.json` pins transitive dependencies and npm integrity hashes. Build fails on missing entrypoints or license files. Tabler's npm package omits its license: `licenses/tabler-LICENSE` is the upstream MIT license retrieved from https://raw.githubusercontent.com/tabler/tabler/dev/LICENSE; Alpine's is from https://raw.githubusercontent.com/alpinejs/alpine/v3.14.9/LICENSE.md. Other licenses are copied from installed packages. Resource metadata includes exact versions, SHA-256, repository, conflicts and dependency order.

Create a private `.env` containing a random `HUB_TOKEN` (32 random bytes encoded as hex). Set `PUBLIC_URL` to the internal address reachable by callers. The default external network is `runtime-os-app-stage_coding`; adapt it only if the deployment uses another authorized network. Run `docker compose build` then `docker compose up -d`. Port 18220 is bound to loopback; authenticated preview endpoints must stay private. The worker has no published ports and only an internal Docker network, CPU/memory/PID limits, a read-only filesystem and expiring tmpfs job storage. Both containers run as `pwuser`, without capabilities or privilege escalation. Chromium's sandbox is required on Linux; a kernel/security-profile incompatibility must be corrected rather than silently disabling it.

For offline installation, export the built image with `docker save` and load it on the destination; runtime does not download packages or CDN files. Keep the prior version and its compose/env backup to roll back. Do not remove shared images or Silo data. Job reports are temporary (one hour); use the delivery helper promptly to retain evidence in the task workspace.

## API

All responses are JSON unless a file is requested. `GET /api/v1/health` returns version/readiness. `GET /api/v1/resources` returns registered dependencies, exact files, full URLs, load order and SHA-256. `/assets/{name}/...` serves pinned package files. `GET /api/v1/themes`, `/templates`, `/components` list metadata; each supports `?q=` and `/{id}`. `/themes/{id}.css` serves CSS variables. Templates provide code, declared component IDs and a business data contract. Tabler includes Bootstrap: do not load both CSS frameworks.

`POST /api/v1/preview` accepts `{ "html": "..." }` with a 2 MiB body limit and `Authorization: Bearer HUB_TOKEN`. It returns HTTP 202 and a job ID; capacity overflow returns 429. Poll `GET /api/v1/preview/{id}/result` using the same authorization. A job returns `running`, `passed` or `failed`, with structured errors, original HTML SHA-256 and desktop/mobile screenshot references. Bundle creation has its own `bundle` or `bundleError` field; wait for it before downloading. Authenticated `/{id}/desktop.png`, `/{id}/mobile.png` and `/{id}/bundle` return binary evidence.

The worker fulfills only registered local asset/theme requests. External URLs, host files, metadata endpoints, WebSockets and service workers are denied. Browser contexts are fresh per viewport. Defaults are 1440×900 and 390×844, a 45-second job browser deadline and two concurrent jobs. Checks cover page/console errors, missing dependencies, external requests, overflow, initialized visible charts, declared required elements and declared safe click interactions. These checks establish rendering behavior, not business correctness. Templates have no invented production data. Their local approval confirmation explicitly awaits a real business API handler.

## Cline and Silo

The built-in `frontend-design` Skill is registered in `coding-agent-node/skills/catalog.json`. Its `deliver.py` helper reads transport settings from environment, writes all attempts to repair-history.json, extracts the offline package and merges `coding_node_delivery_selection.v1` artifact paths/types. It never marks Silo upload complete itself. The existing Runtime transport hashes selected files and archives them to immutable Silo versions. No storage credentials enter the generated page or model prompt.

The native governance gateway supports a private `frontendHub` configuration with `url` and `token`. It adds a task-bound `/frontend` transport to the existing authenticated loopback broker without granting sandbox network access. Each task receives its own broker capability at the reserved, read-only `input/frontend-transport.json` path. Preview IDs are bound to their creating task; another task cannot read its screenshots or bundle. The shared Hub token stays in the trusted gateway. Use the Skill helper's `--query /api/v1/resources` and analogous catalog paths for discovery. Updated gateway images must be deployed through the existing controlled release procedure, with idle checks and exact configuration/image backups. Runtime archive receipts and business acceptance are required for the full P0 delivery claim.

`seccomp_profile.json` is based on Playwright v1.56.1's upstream `utils/docker/seccomp_profile.json`. It permits Chromium's user namespace setup and the inner sandbox chroot syscall. Container capabilities remain dropped; kernel namespace capability checks still apply. This permits the browser sandbox on the target Linux 4.18 host without disabling seccomp or Chromium sandboxing.

## Verification

Run `HUB_URL=... HUB_TOKEN=... EVIDENCE_PATH=... node acceptance.mjs` against a deployment. Run `node offline-check.mjs <evidence.json>` in the worker's working directory before the jobs expire. Five templates are tested using explicitly synthetic data. Offline checks block HTTP, exercise table filtering and local approval, and compare chart values against fixture data. Negative cases inject JS errors, an external metadata request and horizontal overflow, then verify a corrected HTML submission. This deterministic repair test is separate from native Cline model repair and the five real business scenarios in the task brief.

Release evidence is recorded under `docs/frontend-resource-hub-20261113`. Native discovery, task-bound transport, model repair, Runtime Silo upload and authenticated SHA-256 readback are tested separately from rendering-only fixture checks. Business scenarios use explicitly synthetic data; they do not certify production datasets or perform server-side business mutations. Pinning ECharts 6.1.0 and Mermaid 12.3.0 removes the advisories found during implementation; the final npm audit reports zero vulnerabilities. The DataTables manifest includes both its core and matching styling integration after jQuery. Mermaid uses its self-contained classic browser build for file-based offline delivery; optional ESM dependencies are recursively collected without source maps or type declarations.
